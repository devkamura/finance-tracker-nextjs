# バグ報告書

## 症状
画面を読み込んだ直後に、アイコン（Font Awesome）が本来より大きく表示されてレイアウトが崩れ、読み込みが終わると通常の大きさに戻る。

## 再現手順
1. アプリの任意の画面（ヘッダーのある画面、分析画面など）を開く、または再読み込みする
2. 表示された直後のアイコンの大きさを見る

## 期待する動作
読み込み直後から、アイコンが通常の大きさ（文字と同じ程度）で表示される。

## 実際の動作
読み込み直後の一瞬、アイコンが大きく表示され、そのあと通常の大きさに戻る。

## 発生条件
- すべての画面。ページを開いたとき・再読み込みしたとき（通信が遅いほど長く見える）
- 原因：Font Awesome（`@fortawesome/fontawesome-svg-core`）は、アイコンの大きさを決める CSS を、標準ではページの JavaScript が動いてから `<head>` に追加する（`config.autoAddCss = true`）。サーバーから届いた HTML が先に表示されるため、CSS が入るまでの間、アイコンの SVG が本来の大きさで描かれる。

## 影響範囲
Font Awesome のアイコンを使うすべての画面（ヘッダー、分析画面、レシート一覧・登録画面など）。見た目だけで、データや操作への影響はない。

## 緊急度
低

## 修正方針（2026-10-04 ユーザー承認）
Font Awesome の CSS（`@fortawesome/fontawesome-svg-core/styles.css`）をルートのレイアウトで最初から読み込み、JavaScript での自動追加（`config.autoAddCss`）を止める。Next.js で Font Awesome を使うときの標準の設定で、アイコンの見た目は変わらない。

ブランチ：`bug/fontawesome-icon-flash-20261004`。画面の確認は `feature-detailed-analysis` から切った状態で行い（`dev` のコードはローカル DB の分析拡充のマイグレーションに対応していないため）、修正のコミットだけを `dev` に載せ替えて（rebase）マージする。
