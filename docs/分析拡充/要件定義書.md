# 要件定義書（分析拡充）

> ステータス：**確定**（2026-10-03。基本設計書の要確認事項は仮決定で実装を開始）。ヒアリング元：[docs/支出分析機能/メモ.md](../支出分析機能/メモ.md)（2026-10-03）
> 前提：支出分析機能（[docs/支出分析機能/](../支出分析機能/)）のフェーズ0〜3（分析画面の円グラフ・推移グラフ・レシート一覧への絞り込み）は実装済み。

## 1. 概要

カテゴリだけでは集計が粗く、「食費のうち間食はいくらか」「医療費のうち特定の店舗にいくら払っているか」「友人との支出は何に使っているか」「固定費はいくらか」がわからない。

支出を **内訳・費用区分・相手・支払い先** でも分類できるようにし、分析画面でそれらを組み合わせて集計できるようにする。あわせて、分類のためのマスタを整理し、利用者が登録・編集できる **設定画面** を作る。

## 2. ユーザーストーリー

- 2人が、毎月の支出を「何に（カテゴリ・内訳）」「誰と・誰のために（相手）」「どこで（支払い先）」「固定か変動か（費用区分）」の切り口で見て、どこに多く使っているかを把握する。
- レシート登録のたびに同じ内容を選ぶ手間を減らすため、決まった店舗（例：myTOKYOGAS）では、カテゴリなどが自動で入る。
- 自分しか行かない店舗が相方の選択肢を散らかさないよう、支払い先を自分用に登録できる。

## 3. データの構成

| 何を表すか | 項目 | 付ける単位 | 入力 |
|---|---|---|---|
| 何に使ったか | **カテゴリ** ＞ **内訳**（例：食費 ＞ 外食・自炊・間食） | 明細ごと | 内訳を設定したカテゴリでは必須（1つだけ） |
| 固定か変動か | **費用区分**（固定費／変動費） | カテゴリごと | 不要（カテゴリから自動で決まる） |
| 誰と・誰のため | **相手**（例：A／B／ふたり／友人／実家） | 明細ごと | 今の「目的」を置き換える |
| どこで | **支払い先** | レシートごと | グループ全体／ユーザー別に登録 |
| 誰のお金か | **帰属先**（A／B／共同） | 明細ごと | 変更なし（精算・分析の表示対象に使う） |
| その他のラベル | **タグ** | 明細ごと | 任意・複数選択可。今の「シーン」を置き換える |

## 4. 機能要件

### 4.1 設定画面（新設）

ヘッダーに「設定」を追加し、次の登録画面をまとめる。

| 画面 | 内容 | 登録単位 |
|---|---|---|
| カテゴリ | カテゴリごとの **内訳**（追加・編集・削除）と **費用区分**（固定費／変動費）の設定 | グループ全体 |
| 相手 | 相手の選択肢の管理（4.2節） | グループ全体 |
| タグ | タグの追加・編集・削除 | グループ全体（ユーザー別は作らない） |
| 支払い先 | 支払い先の登録と既定値の設定（4.3節）。今の管理画面の「支払い先管理」をここへ移す | グループ全体／ユーザー別 |

### 4.2 相手

- 今の「目的」を「相手」に置き換える。
- 既定の選択肢：メンバーA・メンバーB（グループのメンバーから自動で表示）、ふたり、友人、実家。
- 既定の選択肢は編集・削除できない。表示・非表示の切り替えだけできる。
- 任意の相手を追加・編集・削除できる。
- 管理者だけが編集できる。管理者以外は閲覧のみ。
- 登録・編集画面のプルダウンだけ、ログイン中のユーザー自身を「自分（A）」と表示する。保存する値は変わらず、一覧・詳細・分析では「A」「B」と表示する。

### 4.3 支払い先

- グループ全体の支払い先と、ユーザー別の支払い先を登録できる。
  - グループ全体：管理者だけが編集できる。管理者以外は閲覧のみ。
  - ユーザー別：登録したユーザー本人だけが編集できる。相方のユーザー別の支払い先は閲覧のみ。
- レシート登録画面の支払い先のプルダウンには、グループ全体と自分のユーザー別の支払い先を出す（相方のユーザー別の支払い先は出さない）。
- 相方のユーザー別の支払い先で登録されたレシートも、一覧・詳細では支払い先名を表示し、分析の支払い先別の集計に含める。
- **既定値**：支払い先ごとに、カテゴリ・内訳・相手・帰属先・タグの既定値を設定できる（どれも任意。タグは複数選べる）。
  - レシート登録・編集画面で支払い先を選ぶと、既定値ですべての明細のカテゴリ・内訳・相手・帰属先・タグを上書きする（入力済みの欄も上書きする）。既定値がない項目は未選択にする（入力済みの値・前の支払い先の値は残さない。2026-10-03 変更）。
  - 支払い先を選び直したときも、新しい支払い先の既定値で同じように上書きする。
  - 「該当なし」（手入力）・未選択にしたときは、既定値のない支払い先と同じく、すべて未選択にする。
  - 後から明細を追加したときも既定値を入れる。入った値は自由に変えられる。
  - タグは、明細のタグを既定値のタグに置き換える（追加ではない）。既定値のタグがない支払い先を選んだときは、タグは空になる。
  - 既定値に使われているタグを削除したときは、支払い先の既定値からも外す。
  - OCR（画像の読み取り）で支払い先が入った場合も既定値を入れる（2026-10-04 変更。4.7節）。

### 4.4 タグ

- 今の「シーン」を「タグ」に置き換える。
- 明細ごとに、任意で複数選べる。
- 今回は集計に使わない（一覧・詳細で表示するのみ）。後で集計の対象にする可能性があるため、明細ごとに記録しておく。

### 4.5 カテゴリの整理

- カテゴリ「交際費」を削除する。交際は「相手＝友人」などで表す。
- 内訳を設定したカテゴリでは、レシート登録時に内訳を必ず1つ選ぶ。内訳を設定していないカテゴリでは、内訳の欄を出さない。内訳が1つだけのカテゴリでは、自動で選んだ状態にする。

### 4.6 分析の拡充

- 分析画面の円グラフに次の2つの選択を追加する。
  - **分ける**：カテゴリ／内訳／費用区分／支払い先／相手
  - **絞り込み**：なし／上と同じ項目から1つ（例：カテゴリ＝食費）
- ％の分母は、絞り込み後の支出の合計とする（内訳で分けるときは「内訳なし」も含む）。
- 推移グラフにも同じ絞り込みを使える。
- 内訳表の行から、同じ条件で絞り込んだレシート一覧に移れる（既存の仕組みを広げる）。
- 画面を開いた後の切り替えは、これまでどおりサーバー通信なしで行う。

例

| 知りたいこと | 絞り込み | 分ける |
|---|---|---|
| 食費のうち自炊・外食・間食の割合 | カテゴリ＝食費 | 内訳 |
| 医療費のうち店舗ごとの支出 | カテゴリ＝医療費 | 支払い先 |
| 固定費と変動費の割合 | なし | 費用区分 |
| 固定費の内訳 | 費用区分＝固定費 | カテゴリ |
| 友人との支出は何に使っているか | 相手＝友人 | カテゴリ |
| 食費のうち友人との分 | カテゴリ＝食費 | 相手 |

### 4.7 支払い先の別名（F5。2026-10-04 追加）

手入力や画像の読み取りで入った店名（例：オーケー長津田店）を、登録済みの支払い先（例：オーケー）に寄せる。分析で「よく行く所（登録済みの支払い先）でいくら使っているか」を見られるようにする。

- **ユーザーストーリー**：グループのメンバーが「オーケー長津田店」のような店ごとの名前で登録したレシートも、「オーケー」として集計して、よく行く店ごとの支出を把握したい。
- **別名の登録（設定 ＞ 支払い先）**
  - 支払い先ごとに別名を複数登録できる（1対多。例：オーケー ← オーケー長津田店・オーケー青葉台店）。
  - 一致の判定は完全一致（前後の空白は無視）。部分一致はしない。
  - 同じ別名は、グループの中で1つの支払い先にしか登録できない（グループ全体と自分用をまたいでも不可）。
  - 登録済みの支払い先の名前そのものは別名にできない（逆に、別名として登録済みの名前は支払い先の名前にできない）。
  - 別名を編集できる人は、その支払い先を編集できる人と同じ（グループ全体は管理者、自分用は本人）。
- **過去のレシートの切り替え**：別名を登録したとき、登録済みの支払い先に紐づいておらず、店名が別名と一致するレシートを、その支払い先に切り替える（支払い先IDを設定し、店名も支払い先の名前にそろえる）。
  - 明細の値（カテゴリ・相手など）は変えない（支払い先の既定値は当てない）。
  - 精算確定済みの月のレシートも切り替える（金額は変わらず、精算結果に影響しないため）。
  - 自分用の支払い先の別名で切り替えるのは、その本人が登録したレシートだけ。
  - 別名を削除しても、切り替え済みのレシートは元に戻さない。
- **レシートの登録・編集（手入力）**：入力中は何も変えない。保存したときに、手入力の店名が支払い先の名前か別名と一致したら、支払い先（ID・店名）だけを変換して保存する。既定値は当てない。入力欄の下に「保存時に『○○』として保存されます」と表示する。
  - 対象は、プルダウンに出す支払い先（グループ全体と自分用の、非表示でないもの）。
- **画像の読み取り**：読み取った店名が、支払い先の名前か別名と一致したら、その支払い先を自動で選び、プルダウンで選んだときと同じく既定値（カテゴリ・内訳・相手・帰属先・タグ）ですべての明細を上書きする。
- **手入力と画像の読み取りの違い**

  | | 画像の読み取り | 手入力 |
  |---|---|---|
  | 変換するタイミング | 読み取った直後 | 保存したとき（入力中は変えない） |
  | 変換するもの | 支払い先を選び、既定値ですべての明細を上書き | 支払い先（ID・店名）だけ |
  | 既定値 | 入れる | 入れない（入力した明細のまま保存） |
  | 理由 | 読み取った直後は明細がまだ確定しておらず、既定値を入れても困らない | 手入力には意図があり、明細も入力済みのことがあるため、勝手に上書きしない（既定値が欲しければプルダウンで選び直す） |

- **分析の支払い先**：「絞り込み」「分ける」の支払い先は、登録済みの支払い先（支払い先ID）で集計し、紐づいていないレシートは「登録外（手入力）」1つにまとめる。
  - 選択肢は上から「グループ全体」「自分用（ログインしているユーザー）」「相方の自分用」「登録外（手入力）」の順に並べ、見出しで区切る。表示対象（全体／ユーザー別）によらず同じ選択肢にする。
  - 非表示の支払い先は、12ヶ月のレシートで使われているときだけ選択肢に出す。
- **完了基準**
  1. 別名「オーケー長津田店」を登録すると、過去のレシート（精算確定済みの月を含む）が「オーケー」に切り替わる。
  2. 「オーケー長津田店」と手入力すると入力欄の下に案内が出て、保存すると「オーケー」として保存される。明細の値は入力したまま。
  3. 画像読み取りで「オーケー長津田店」を読み取ると「オーケー」が選ばれ、既定値が明細に入る。
  4. 分析の支払い先の選択肢が上の並びになり、「オーケー」に1の分が集計される。
  5. 新規・既存のテストがすべて通る。

## 5. 既存機能への影響

- レシート登録・編集画面：目的 → 相手、シーン → タグ、内訳の欄の追加、支払い先の既定値の自動入力、支払い先の選択肢の変更。
- レシート一覧・詳細：目的 → 相手、シーン → タグ、内訳の表示。
- 一括入力・複製登録：目的 → 相手、シーン → タグ、内訳への対応。
- 管理画面：支払い先管理を設定画面へ移す。
- 精算：影響なし（帰属先は変更しない）。
- 分析：「分ける」「絞り込み」の追加。支払い先は登録済みの支払い先と「登録外（手入力）」で集計する（F5）。
- 既存データ：目的 → 相手、シーン → タグ、交際費の明細を移し替える（基本設計書で方針を決める）。

## 6. 対象外

- 任意タグの集計（後で追加する可能性あり）
- 絞り込みの複数組み合わせ（足りなければ後で拡張）
- 予算設定・予算進捗（支出分析機能のフェーズ4・5。保留中）

## 7. 完了基準

- 設定画面で、カテゴリの内訳・費用区分、相手、タグ、支払い先（既定値を含む）を要件どおりの権限で登録・編集できる。
- レシート登録・編集画面で、内訳・相手・タグを選べ、支払い先の既定値が要件どおりに入る。
- 分析画面で、4.6節の例をすべて集計でき、内訳表から同じ条件のレシート一覧に移れる。
- 既存のレシートが、移し替えたうえで一覧・詳細・分析・精算で正しく表示される。
- 追加したテスト（単体・結合）と既存テストがすべて通る（E2E はテスト環境の制約により実施せず、手動で確認する）。
