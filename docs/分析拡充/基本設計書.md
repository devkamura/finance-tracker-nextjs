## 1. 全体の進め方

規模が大きいため、データの種類ごとに「設定画面・登録画面・表示」をまとめて作る機能追加に分け、最後に分析を作る。【要確認 Q1】

**ブランチ運用（2026-10-03 決定）**

```text
main（全体が完成するまで触らない）
 └ dev
    └ feature-detailed-analysis（分析拡充の中心のブランチ）
       ├ feature-i0008-category-breakdown   F1
       ├ feature-i0009-counterpart-tag      F2
       ├ feature-i0010-payee                F3
       ├ feature-i0011-analytics-axes       F4
       └ feature-i0012-payee-alias          F5（2026-10-04 追加）
```

- 各機能追加は中心のブランチから切り、画面で確認してから中心のブランチに PR でマージする。
- F1〜F4 がすべてそろったら、中心のブランチを dev にマージし、dev で全体のテストを行う。問題がなければ main にマージする。

| 順 | 機能追加 | 内容 | DB変更 |
|---|---|---|---|
| F1 | 設定画面の土台＋カテゴリの内訳・費用区分 | 設定画面の新設（ヘッダーに「設定」）、カテゴリの内訳・費用区分の設定、登録画面の内訳の欄、一覧・詳細の内訳の表示、交際費の削除 | あり |
| F2 | 相手・タグ | 目的 → 相手、シーン → タグの置き換え（設定画面・登録画面・表示・既存データの移し替え） | あり |
| F3 | 支払い先 | 設定画面への移設、グループ全体／ユーザー別、プルダウンの絞り込み、既定値の設定と自動入力 | あり |
| F4 | 分析の拡充 | 「分ける」「絞り込み」（カテゴリ・内訳・費用区分・支払い先・相手）、レシート一覧への絞り込みの拡張 | なし |
| F5 | 支払い先の別名（2026-10-04 追加） | 手入力・画像読み取りの店名を登録済みの支払い先に寄せる別名、過去のレシートの切り替え、分析の支払い先を「登録済み＋登録外」に。要件は要件定義書 4.7節、設計は詳細設計書 F5 | あり |

- F1〜F3 は互いに独立しており、順番を入れ替えられる。F4 は F1〜F3 のデータがそろってから作る。
- 本来の目的は分析（F4）のため、F1（内訳・費用区分）を先に作り、分析で使う軸から順にそろえる。

## 2. 画面設計

### 2.1 画面一覧

| 画面 | 区分 | 役割 |
|---|---|---|
| 設定（新設） | 新規 | ヘッダーの「設定」から開く。下のタブ（または一覧）で各登録画面へ |
| 設定 ＞ カテゴリ | 新規 | カテゴリごとの内訳の追加・編集・削除、費用区分の設定 |
| 設定 ＞ 相手 | 新規 | 相手の表示・非表示、任意の相手の追加・編集・削除 |
| 設定 ＞ タグ | 新規 | タグの追加・編集・削除 |
| 設定 ＞ 支払い先 | 既存を移設・変更 | グループ全体／ユーザー別の支払い先と既定値 |
| 管理画面 | 既存を変更 | 「支払い先管理」を外す（ユーザー管理は残す） |
| レシート登録・編集 | 既存を変更 | 内訳・相手・タグ、支払い先の既定値の自動入力 |
| レシート一覧・詳細 | 既存を変更 | 内訳・相手・タグの表示 |
| 分析 | 既存を変更 | 「分ける」「絞り込み」 |

### 2.2 画面遷移

| 今いる画面 | 操作 | 移動先 |
|---|---|---|
| どの画面でも | ヘッダーの「設定」 | 設定（最初はカテゴリ） |
| 設定 | タブ（カテゴリ／相手／タグ／支払い先） | 各登録画面 |
| 管理画面 | （「支払い先管理」のメニューはなくなる） | ― |

設定画面は全員が開ける。編集できるかどうかは画面ごとの権限（4.3節）で決め、編集できない人には閲覧だけを表示する。

### 2.3 設定 ＞ カテゴリ

```text
設定
[カテゴリ | 相手 | タグ | 支払い先]
┌──────────────────────────────┐
│ 食費                      費用区分 [変動費 ▼] │
│   内訳：外食 ✎ ／ 自炊 ✎ ／ 間食 ✎   [+ 追加] │
├──────────────────────────────┤
│ 水道光熱費                費用区分 [固定費 ▼] │
│   内訳：なし                         [+ 追加] │
└──────────────────────────────┘
```

- カテゴリ自体の追加・削除はしない（カテゴリはアプリ共通のマスタのまま）。
- 内訳の名前は、同じカテゴリの中で重複できない。

### 2.4 設定 ＞ 相手

```text
相手
  A（メンバー）       [表示 ●]
  B（メンバー）       [表示 ●]
  ふたり（既定）      [表示 ●]
  友人（既定）        [表示 ●]
  実家（既定）        [表示 ○]   ← 非表示にした例
  会社の同僚     ✎ 🗑 [表示 ●]   ← 任意で追加したもの
  [+ 相手を追加]
```

- メンバー（A・B）はグループのメンバーから自動で表示する。名前は管理画面の表示名に連動する。
- 非表示にした相手は、登録画面のプルダウンに出さない。すでにその相手を付けた明細は、一覧・詳細・分析でそのまま表示する。

### 2.5 設定 ＞ タグ

- タグの追加・編集・削除のみ。並び順は登録順（または名前順）。

### 2.6 設定 ＞ 支払い先

```text
支払い先
[グループ全体 | 自分用 | Bさん用（閲覧のみ）]
  myTOKYOGAS     既定値：水道光熱費／―／ふたり／共同   ✎ 🗑
  〇〇スーパー   既定値：なし                          ✎ 🗑
  [+ 支払い先を追加]

（編集）
  名前：[myTOKYOGAS]
  既定値（任意）
    カテゴリ [水道光熱費 ▼]  内訳 [― ▼]  相手 [ふたり ▼]  帰属先 [共同 ▼]
    タグ [朝食] [夕食] …（複数選択）
```

- 既定値の内訳は、選んだカテゴリの内訳だけを選べる。
- 既存の支払い先はすべて「グループ全体」として引き継ぐ。

### 2.7 レシート登録・編集画面

```text
支払い先 [myTOKYOGAS ▼]      ← 選ぶと既定値を全明細に入れる
…
明細1
  品目 [ガス代]  金額 [8,000]
  カテゴリ [水道光熱費 ▼]  内訳（内訳があるカテゴリだけ表示）[― ▼]
  相手 [ふたり ▼]          帰属先 [共同 ▼]
  タグ [＋選ぶ]（任意・複数）
```

- 「目的」の欄を「相手」に、「シーン」の欄を「タグ」に置き換える。
- 支払い先のプルダウンは「グループ全体」と「自分用」の支払い先を出す（区別が分かるよう見出しを分ける）。
- 一括入力（`BulkInputModal`）・複製登録も同じ項目に合わせる。

### 2.8 レシート一覧・詳細

- 明細のバッジ：カテゴリ（内訳があれば「食費 ＞ 外食」）、相手、帰属先、税区分、タグ。

### 2.9 分析画面

```text
分析
[ 円グラフ | 推移グラフ ]
条件：全体 ／ 食費 ／ 内訳で分ける ▼   ← 折りたたみ。開くと下の3つが出る（スマホでグラフが下に押し出されないように）
  表示対象：[全体|A|B]  □共同を含める
  絞り込み：[なし ▼] [食費 ▼]   ← 対象にする支出（ⓘで説明）
  分ける：[カテゴリ ▼]            ← 対象の支出を何ごとに区切るか（ⓘで説明）
◀ 2026年7月 ▼ ▶
（円グラフ）
食費の合計 40,000円        ← 絞り込みに合わせて合計の名前を変える
（内訳表：行をタップすると同じ条件のレシート一覧へ）
```

- 「分ける」：カテゴリ／内訳／費用区分／支払い先／相手。
- 「絞り込み」：なし／カテゴリ／内訳／費用区分／支払い先／相手 を選び、続けてその値（例：食費）を選ぶ。
- 推移グラフは、今の「カテゴリ［総支出 ▼］」の選択を「絞り込み」に置き換える（総支出＝絞り込みなし）。
- 選択状態は、これまでどおり URL に保存する（戻る・再読み込みで復元）。

## 3. 業務ロジック

### 3.1 内訳

- 内訳が1つ以上あるカテゴリでは、内訳は必須。1つだけなら自動で選ぶ。
- カテゴリを変えたら、内訳は選び直し（新しいカテゴリの内訳が1つだけなら自動で選ぶ）。
- 既存のレシート（内訳なし）を編集して保存するときの扱いは【要確認 Q8】。
- 分析で「内訳で分ける」とき、内訳のない明細は「内訳なし」としてまとめる。

### 3.2 費用区分

- カテゴリごとに固定費／変動費を持つ。初期値は【要確認 Q5】。
- 分析では、集計するときのカテゴリの費用区分を使う。費用区分を変えると、過去の月の集計も新しい区分で表示される（明細ごとに保存しない）。【要確認 Q6】

### 3.3 相手

- 明細ごとに1つ。必須とするかは【要確認 Q3】。
- プルダウンには表示中の相手を出し、ログイン中のユーザーは「自分（A）」と表示する。

### 3.4 支払い先の既定値

- 支払い先を選んだとき（最初・選び直し）：カテゴリ・内訳・相手・帰属先・タグを、すべての明細で既定値に上書きする。既定値のない項目は未選択にする（入力済みの値・前の支払い先の値は残さない。2026-10-03 ユーザー確認のうえ変更）。「該当なし」・未選択にしたときも、既定値のない支払い先と同じくすべて未選択にする。
- 内訳の既定値がなければ、カテゴリの内訳が1つだけのとき自動で選ぶ（3.1節と同じ）。
- 明細を追加したとき：選択中の支払い先の既定値を入れる。
- 既定値の内訳が、既定値のカテゴリに属していない（後から内訳を消した等）場合は、内訳は入れない。
- タグ：既定値のタグがあれば、明細のタグを既定値のタグに置き換える（追加ではない。2026-10-03 ユーザー確認済み）。既定値のタグがなければタグは空になる。
- 編集画面を開いたときは、保存済みの内容を表示する（既定値で上書きしない）。支払い先を選び直したときだけ既定値を入れる。

### 3.5 支払い先のプルダウンと表示

- プルダウン：グループ全体＋自分用。相方用は出さない。
- 一覧・詳細・分析：レシートに保存された支払い先名で表示・集計する（相方用・手入力の支払い先も含む）。
- 分析の「支払い先で分ける」は、支払い先名ごとに集計する（手入力の支払い先も名前で集計される）。

### 3.6 削除したときの扱い

内訳・任意の相手・タグ・支払い先を削除したときに、それを使っている既存の明細・レシートをどうするか。【要確認 Q4】

### 3.7 分析の集計

- 既存の「月×カテゴリ×帰属先」の集約に、内訳・相手・支払い先を加えて集約する（費用区分はカテゴリから求める）。
- 「分ける」の項目ごとに合計し、「絞り込み」の条件に当てはまる行だけを使う。表示対象（全体／A／B、共同トグル）、返金のマイナス、％の分母、マイナスの扱いは既存のルールのまま。
- レシート一覧への絞り込み（既存の `category`・`scope` など）に、内訳・費用区分・支払い先・相手の条件を追加する。一覧の「うち〇〇円」と合計は、分析と同じ計算で一致させる。

## 4. データ設計

### 4.1 新規・変更するデータ

| データ | 区分 | 主な項目 |
|---|---|---|
| カテゴリの設定 | 新規 | グループ、カテゴリ、費用区分（固定費／変動費） |
| 内訳 | 新規 | グループ、カテゴリ、名前、並び順 |
| 相手 | 新規（目的を置き換え） | グループ、種類（メンバー／既定／任意）、メンバーの場合はユーザー、名前、表示・非表示、並び順 |
| タグ | 新規（シーンを置き換え） | グループ、名前 |
| 明細 | 変更 | 内訳（任意）、相手（目的の代わり）を追加。目的は移し替え後に削除 |
| 明細×タグ | 新規（明細×シーンを置き換え） | 明細、タグ |
| 支払い先 | 変更 | 登録者（空＝グループ全体、値あり＝そのユーザー用）、既定値（カテゴリ・内訳・相手・帰属先） |
| 支払い先×タグ | 新規 | 支払い先、タグ（既定値のタグ。複数。タグを削除したら既定値から外す） |
| カテゴリ | 変更 | 「交際費」を削除 |

- 内訳・相手・タグ・カテゴリの設定は、グループごとに持つ（今の目的・シーンはアプリ共通だったが、グループごとに編集できるようにするため）。
- 支払い先の帰属先の既定値は「設定しない／共同／メンバー」のいずれか。
- 支払い先の名前の重複のルールは【要確認 Q9】。

### 4.2 権限

| データ | 参照 | 編集 |
|---|---|---|
| カテゴリの設定・内訳 | グループのメンバー全員 | 【要確認 Q2】（案：管理者のみ） |
| 相手 | グループのメンバー全員 | 管理者のみ（既定の相手は表示・非表示のみ） |
| タグ | グループのメンバー全員 | グループのメンバー全員（集計に使わないため。Q2：2026-10-03 ユーザー確認済み） |
| 支払い先（グループ全体） | グループのメンバー全員 | 管理者のみ |
| 支払い先（ユーザー用） | グループのメンバー全員 | 登録したユーザー本人のみ |

画面でボタンを隠すだけでなく、データ側の権限（RLS）でも制限する。

## 5. 既存データの移し替え

| 対象 | 方針（案） |
|---|---|
| 目的 → 相手 | 【要確認 Q7】（案：生活維持 → ふたり、個人 → 明細の帰属先のメンバー（共同ならふたり）、仕事 → 個人と同じく帰属先のメンバー（共同ならふたり。相手「仕事」は作らない：2026-10-03 ユーザー確認済み）、家族 → 実家、友人 → 友人） |
| シーン → タグ | 同じ名前のタグをグループに作り、明細に付いていたシーンをそのタグに移す |
| 交際費 | F1 で削除（Q7 確定）。既存の明細はカテゴリを「その他」にし、内訳は外す。相手の設定はしない |
| 支払い先 | すべて「グループ全体」として引き継ぐ。既定値は空 |
| 内訳 | 既存の明細は「内訳なし」のまま |

移し替えはマイグレーションで行い、ローカルで試してから本番に反映する。本番に反映する前に、移し替え対象の件数を確認する。

## 6. 非機能

- 分析のデータ量：集約のキーが増えるため、画面に渡す行数が増える（2人・1年分で数千行程度の見込み）。それでも初回の取得は1回だけで、切り替えはこれまでどおり通信なし。実測で重い場合は、集約のキーを絞り込みに使う分だけにする等を詳細設計で検討する。
- 既存の精算の計算・結果は変えない（帰属先・按分は変更しない）。

## 7. テスト観点（概要）

- 設定画面：各データの登録・編集・削除、権限（管理者以外・相方の支払い先は編集できない）、データ側の権限（RLS）
- 登録画面：内訳の必須・自動選択、相手の「自分（A）」表示、支払い先の既定値の上書き・既定値のない項目を未選択にすること・明細追加時、プルダウンに相方用の支払い先が出ないこと
- 分析：要件定義書4.6節の例の集計、％の分母、内訳なし、費用区分、支払い先名での集計、一覧の合計との一致
- 移し替え：目的・シーン・交際費・支払い先が方針どおりに移ること、移し替え後も一覧・詳細・分析・精算が正しく表示されること
- 回帰：既存テストがすべて通ること。E2E は実施せず、手動テスト仕様書で確認する

## 8. 既存機能への影響

- レシート登録・編集・一括入力・複製登録：目的・シーンを使っている処理をすべて相手・タグに置き換える（`ReceiptForm`・`ReceiptItemCard`・`ReceiptItemsSection`・`BulkInputModal`・`create-receipt`・`update-receipt`・`receipt-rules`・`duplicate`・`shared`）。
- レシート一覧・詳細：`queries.ts`・`ReceiptItemBadges`。
- 管理画面：支払い先管理（`PayeeManager`・`create/update/delete-payee`）を設定画面へ移す。
- 分析：集約のキーと画面の追加。精算は変更しない。

## 9. 対象外

要件定義書6章のとおり（任意タグの集計、絞り込みの複数組み合わせ、OCR からの既定値の自動入力、予算）。
