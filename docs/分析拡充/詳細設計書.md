## F1：設定画面の土台＋カテゴリの内訳・費用区分

ブランチ：`feature-i0008-category-breakdown`（`feature-detailed-analysis` から作成）
ステータス：**画面確認済み**（2026-10-03）

### 1. 対象範囲

| 区分 | 内容 |
|---|---|
| DB | カテゴリの費用区分の初期値、グループごとの費用区分（`category_settings`）、内訳（`category_breakdowns`）、明細の内訳（`receipt_details.breakdown_id`） |
| 設定画面 | `/settings` を新設（ヘッダーの「設定」は `/settings/categories` へ。`/settings` は `next.config.ts` の `redirects` でカテゴリへ転送）。F1 ではカテゴリのタブのみ（費用区分と内訳の追加・名前の変更・表示/非表示・削除） |
| 登録・編集画面 | 内訳の欄（必須・自動選択・非表示の既存値の表示）、一括入力の内訳 |
| 一覧・詳細 | 「食費 ＞ 外食」の表示 |

カテゴリ「交際費」の削除も F1 で行う（`20261003000003_delete_social_category.sql`）。既存の交際費の明細はカテゴリを「その他」にし、内訳は外す。相手は設定しない（基本設計書 Q7：ユーザー確認済み）。

### 2. DB（`supabase/migrations/20261003000002_category_breakdowns.sql`）

| 対象 | 内容 |
|---|---|
| `categories.default_cost_type` | 費用区分の初期値（`fixed`／`variable`）。賃料・水道光熱費・通信費は `fixed`、それ以外は `variable`（基本設計書 Q5） |
| `category_settings` | グループ×カテゴリの費用区分。行がなければ `default_cost_type` を使う |
| `category_breakdowns` | グループ×カテゴリの内訳。名前はカテゴリ内で一意。`is_hidden`（非表示）、`sort_order`（末尾に追加） |
| `receipt_details.breakdown_id` | 明細の内訳（任意）。`on delete restrict`（使われている内訳は削除できない。基本設計書 Q4） |
| トリガー `check_receipt_detail_breakdown` | 明細の内訳が、明細のカテゴリ・レシートのグループの内訳であることを保証する |
| RLS | 参照はグループのメンバー全員、書き込みは管理者のみ（`is_group_admin`。基本設計書 Q2） |

### 3. 共通処理

| ファイル | 内容 |
|---|---|
| `lib/receipts/breakdowns.ts` | 型（`CategoryBreakdown`・`CostType`）、表示中の内訳、内訳が必須か、自動で選ぶ内訳、内訳がカテゴリのものか（画面・入力チェック共通） |
| `lib/settings/queries.ts` | 内訳の取得、カテゴリと費用区分の取得（グループの設定 → 初期値の順） |
| `lib/settings/admin.ts` | 設定の Server Action で使う、管理者の確認 |
| `lib/actions/settings/*.ts` | 内訳の追加・変更（名前・表示/非表示）・削除、費用区分の変更 |

### 4. 登録・編集画面

- `ReceiptItem.breakdownId`、`MasterData.breakdowns`（非表示を含む）を追加。
- 内訳の欄は、カテゴリに表示中の内訳がある（または非表示の内訳が選ばれている）ときだけ表示する。非表示の内訳は「（非表示）」付きで、選ばれている場合だけ選択肢に残す。
- カテゴリを変えたら内訳を選び直し、表示中の内訳が1つだけなら自動で選ぶ（`ReceiptForm` の `withBreakdownForCategory`）。一括入力も同じ。
- 一括入力：カテゴリを選ぶと内訳の選択肢が出る（「各項目で選ぶ」＝各項目で選び直し）。
- 入力チェック（`validateReceiptForm` の第3引数に内訳）：表示中の内訳があるカテゴリでは必須、選んだ内訳はそのカテゴリのもの（非表示の既存値は可）。Server Action（登録・更新）でも同じチェックを行う。既存の内訳なしのレシートも、編集して保存するときは内訳が必要（基本設計書 Q8）。
- 複製登録は明細をそのままコピーするため、内訳も引き継がれる。

## F2：相手・タグ

ブランチ：`feature-i0009-counterpart-tag`（`feature-detailed-analysis` から作成）
ステータス：**画面確認済み**（2026-10-03。PR #29 で中心のブランチにマージ）

### 1. 対象範囲

| 区分 | 内容 |
|---|---|
| DB | 相手（`counterparts`）・タグ（`tags`・`receipt_detail_tags`）の新設、明細の相手（`receipt_details.counterpart_id`）、目的・シーンからの移し替え、目的・シーンの削除 |
| 設定画面 | 「相手」「タグ」のタブを追加（`/settings/counterparts`・`/settings/tags`） |
| 登録・編集画面 | 目的 → 相手（「自分（A）」の表示）、シーン → タグ。一括入力の目的 → 相手 |
| 一覧・詳細 | 「目的」→「相手」、「シーン」→「タグ」のバッジ |

### 2. DB（`supabase/migrations/20261003000004_counterparts_tags.sql`）

| 対象 | 内容 |
|---|---|
| `counterparts` | グループの相手。`kind`：`member`（メンバー。`user_id` を持ち、名前は持たない）／`default`（ふたり・友人・実家）／`custom`（任意）。`is_hidden`、`sort_order`（メンバー 0、既定 1〜3、任意は末尾） |
| 一意性 | メンバーはグループ×ユーザーで1つ。既定・任意の名前はグループ内で重複できない |
| トリガー `protect_builtin_counterparts` | メンバー・既定の相手は名前・種類・ユーザーを変えられない（表示・非表示と並び順のみ） |
| トリガー（自動作成） | グループ作成時に既定の相手（`groups` の after insert）、メンバー参加時にメンバーの相手（`group_members` の after insert / update of user_id。招待中は作らず、参加して `user_id` が入った時点で作る） |
| `receipt_details.counterpart_id` | 明細の相手（必須。基本設計書 Q3）。`on delete restrict`（使われている相手は削除できない。Q4） |
| トリガー `check_receipt_detail_counterpart` | 明細の相手が、レシートのグループの相手であることを保証する |
| `tags` | グループのタグ。名前はグループ内で一意。`is_hidden`、`sort_order` |
| `receipt_detail_tags` | 明細×タグ。`tag_id` は `on delete restrict`。トリガー `check_receipt_detail_tag` でグループの一致を保証する |
| RLS | 参照はグループのメンバー全員。相手は管理者のみ編集でき、追加・削除できるのは `custom` だけ。タグはグループのメンバー全員が編集できる（集計に使わないため。Q2：ユーザー確認済み） |

**移し替え（基本設計書 5章・Q7 の案のとおり）**

| 目的 | 相手 |
|---|---|
| 生活維持 | ふたり |
| 個人 | 明細の帰属先のメンバー（共同のときは ふたり） |
| 仕事 | 個人と同じ（明細の帰属先のメンバー。共同のときは ふたり）。相手「仕事」は作らない（ユーザー確認済み） |
| 家族 | 実家 |
| 友人 | 友人 |
| 上記以外 | 同じ名前の任意の相手 |

- シーン → タグ：今のシーンをすべて同じ名前のタグとして各グループに作り（並び順はシーンの順）、明細のシーンをタグに移す。
- 移し替えのあと、`receipt_details.purpose_id`・`receipt_detail_scenes`・`scenes`・`purposes` を削除する（古いアプリは動かなくなる。本番デプロイ前チェックリスト参照）。
- 新しく作るグループには、タグは作らない（設定画面で追加する）。

### 3. 共通処理

| ファイル | 内容 |
|---|---|
| `lib/receipts/labels.ts` | 型（`Counterpart`・`Tag`）、プルダウンの表示（「自分（A）」「（非表示）」）、選択肢（表示中＋選ばれている非表示）、グループの相手・タグかの判定 |
| `lib/settings/queries.ts` | `getCounterparts`（メンバーの名前は表示名。グループから外れたメンバーの相手は含めない）、`getTags` |
| `lib/actions/settings/counterparts.ts` | 任意の相手の追加・名前の変更・削除、表示・非表示（メンバー・既定も可） |
| `lib/actions/settings/tags.ts` | タグの追加・名前の変更・表示/非表示・削除（メンバー全員。`requireGroupMember` でログイン・グループ所属だけを確認する） |
| `components/settings/NamedItemListManager.tsx` | 相手・タグの設定画面の共通の一覧（追加・名前の変更・表示/非表示・削除） |

### 4. 登録・編集画面

- `ReceiptItem.purposeId`・`sceneIds` → `counterpartId`・`tagIds`。`MasterData.counterparts`・`tags`（非表示を含む）。
- 相手のプルダウン：表示中の相手（＋編集時に選ばれている非表示の相手）。ログイン中のユーザー自身は「自分（A）」と表示する（編集画面にも `currentUserId` を渡す）。
- タグ：表示中のタグ（＋選ばれている非表示のタグ）をボタンで複数選択。タグが1つもないときは欄を出さない。
- 入力チェック（`validateReceiptForm` の第4引数に相手・タグ）：相手は必須、相手・タグはグループのもの（非表示の既存値は可）。Server Action（登録・更新）でも同じチェックを行う。
- 複製登録：相手・タグは元の明細のまま（帰属先だけを置き換える既存のルールは変えない）。

## F3：支払い先

ブランチ：`feature-i0010-payee`（`feature-detailed-analysis` から作成）
ステータス：**画面確認済み**（2026-10-03。PR #30 で中心のブランチにマージ）

### 1. 対象範囲

| 区分 | 内容 |
|---|---|
| DB | 支払い先の登録者（グループ全体／自分用）、表示・非表示、既定値（カテゴリ・内訳・相手・帰属先・タグ）、名前の重複のルール、RLS |
| 設定画面 | 「支払い先」のタブを追加（`/settings/payees`）。グループ全体／自分用／相方用（閲覧のみ）を切り替えて表示 |
| 管理画面 | 「支払い先管理」を外し、`/admin/payees` のページを削除する（転送はしない） |
| 登録・編集画面 | 支払い先のプルダウンを「グループ全体」「自分用」の見出しに分ける。支払い先を選んだとき・明細を追加したときに既定値を入れる |

### 2. DB（`supabase/migrations/20261003000005_payee_scope_defaults.sql`）

| 対象 | 内容 |
|---|---|
| `payees.owner_user_id` | 登録者。null＝グループ全体、値あり＝そのユーザー用。既存の支払い先は null のため、すべてグループ全体として引き継ぐ |
| `payees.is_hidden` | 非表示（使われている支払い先は削除できないため。基本設計書 Q4） |
| `payees.default_category_id`・`default_breakdown_id`・`default_counterpart_id` | 既定値。参照先が削除されたら `on delete set null`（その既定値だけを「設定しない」に戻す）。内訳はカテゴリの既定値があるときだけ（check 制約） |
| `payees.default_owner_joint`・`default_owner_user_id` | 帰属先の既定値。設定しない（false・null）／共同（true・null）／メンバー（false・ユーザー）。両方は不可（check 制約） |
| 一意性（基本設計書 Q9） | `payees_group_name_uniq`（グループ全体の中）、`payees_owner_name_uniq`（同じユーザーの自分用の中）。グループ全体と自分用の間は、トリガー `check_payee_name_across_scopes`（`20261003000007_payee_name_across_scopes.sql`）で重複を防ぐ（エラーコードは 23505。メッセージで「グループ全体と重なった」「誰かの自分用と重なった」を区別し、画面のメッセージを出し分ける）。ユーザーどうしの自分用の間の重複は許す |
| トリガー `check_payee_defaults` | 登録者・グループは変えられない。自分用の登録者はグループのメンバー。既定値の内訳は既定値のカテゴリ・グループのもの、相手はグループのもの、帰属先のメンバーはグループのメンバー（変更したときだけ確認し、後から外れたメンバーの保存済みの値は残す） |
| `receipts.payee_id` | 変更なし（外部キーの既定の動作で、使われている支払い先は削除できない） |
| RLS | 参照はグループのメンバー全員（相方用も読める）。グループ全体は管理者のみ（`is_group_admin`）、自分用は本人のみ（`owner_user_id = auth.uid()`）が書き込める |

**既定値のタグ（`supabase/migrations/20261003000006_payee_default_tags.sql`。2026-10-03 追加）**

| 対象 | 内容 |
|---|---|
| `payee_default_tags` | 支払い先×タグ（既定値のタグ。複数）。`payee_id`・`tag_id` とも `on delete cascade`（タグを削除したら既定値から外す。ユーザー確認済み） |
| トリガー `check_payee_default_tag` | 既定値のタグが、支払い先のグループのタグであることを保証する |
| RLS | 参照はグループのメンバー全員。書き込みは支払い先と同じ権限（グループ全体は管理者、自分用は本人） |

### 3. 共通処理

| ファイル | 内容 |
|---|---|
| `lib/receipts/payees.ts` | 型（`Payee`・`PayeeDefaults`。既定値は明細と同じ文字列の形で、タグは `tagIds`）、DBの行との変換、プルダウンの選択肢（グループ全体／自分用＋選ばれている相方用・非表示）、既定値の自動入力（`applyPayeeDefaults`）、既定値の説明・入力チェック |
| `lib/settings/queries.ts` | `getPayees`（グループ全体・全員の自分用・非表示を含む。名前順） |
| `lib/settings/admin.ts` | `requireGroupMembership`（ログイン・グループ所属を確認し、ユーザーIDと管理者かどうかを返す。権限の判定は呼び出し側） |
| `lib/actions/settings/payees.ts` | 支払い先の追加（`scope`：`shared`＝グループ全体／`own`＝自分用）・変更（名前・既定値・表示/非表示）・削除。既定値のタグは `payee_default_tags` を入れ替えて保存する（追加時にタグの保存に失敗したら、追加した支払い先を取り消す）。旧 `lib/actions/{create,update,delete}-payee.ts` を置き換える |
| `lib/receipts/shared.ts` | `resolvePayeeName` を、取得済みの支払い先の一覧で判定する形に変更。選べるのはグループ全体と自分用の表示中のもの。更新では保存済みの支払い先（相方用・非表示）も可 |

### 4. 登録・編集画面

- `MasterData.payees` を `Payee[]`（グループ全体・全員の自分用・非表示を含む）にする。
- プルダウン：「該当なし」の下に、見出し「グループ全体」「自分用」で分けて出す。編集中のレシートの支払い先が相方用・非表示のときは、その支払い先を「〇〇（Bさん用）」「〇〇（非表示）」として残す（そのまま保存できる）。
- 既定値の自動入力（基本設計書 3.4節。`ReceiptForm` の `updateState`・`addItem`）
  - 支払い先を選んだ・選び直したとき：全明細のカテゴリ・内訳・相手・帰属先・タグを既定値で上書きする（入力済みの欄も上書き）。既定値のない項目は未選択にする（前の支払い先の値も残さない。ユーザー確認済み）。
  - 内訳は、内訳の既定値があればそれ、なければカテゴリの内訳が1つだけのとき自動で選ぶ（それ以外は未選択）。
  - 内訳の既定値がカテゴリに属していない・非表示、相手の既定値が非表示、帰属先の既定値のメンバーがグループにいないときは、その項目は未選択にする。

  - 明細を追加したとき：選択中の支払い先の既定値を入れる。
  - 編集画面を開いたときは、保存済みの内容のまま（支払い先を選び直したときだけ既定値を入れる）。
  - 「該当なし」・未選択に変えたときも、既定値のない支払い先と同じくすべて未選択にする（ユーザー確認済み）。OCR で支払い先が入ったときは既定値を入れない（明細も OCR の結果のまま）（要件定義書 4.3節：対象外）。OCR の支払い先名の照合は、プルダウンに出る支払い先（グループ全体・自分用）だけで行う。
- 複製登録：相方分のレシートも同じ支払い先（ID・名前）のまま（自分用の支払い先でも、表示・集計は支払い先名で行うため問題ない）。

| `check_payee_alias`（トリガー） | `group_id` を支払い先のグループにそろえる。支払い先の名前と同じ別名は 23505（`payee alias conflicts with a payee name`） |
| `check_payee_name_not_alias`（トリガー） | 支払い先の名前の追加・変更で、別名と同じ名前は 23505（`payee name conflicts with an alias`） |
| RLS | 参照：グループのメンバー。削除：支払い先を編集できる人（グループ全体は管理者、自分用は本人）。**追加のポリシーは作らない**（直接の追加は不可。`add_payee_alias` からだけ追加し、過去のレシートの切り替えを必ず一緒に行う） |
| `add_payee_alias(p_payee_id, p_name)` | security definer。支払い先の編集権限を確かめ（グループ外は P0002、権限なしは 42501）、別名を追加し、`payee_id is null` かつ `normalize_payee_name(payee_name)` が別名と一致するレシートの `payee_id`・`payee_name` を切り替える。自分用の支払い先は `created_by` が本人のレシートだけ。戻り値は `{ id, name, converted }` |

- 精算確定済みの月のレシートは RLS で更新できないため、security definer で更新する（金額・明細は変えないため精算結果に影響しない）。
- 別名を削除しても、切り替え済みのレシートは戻さない。

### 3. 共通処理

| ファイル | 内容 |

| `lib/receipts/payees.ts` | `Payee.aliases`（名前順）、`PAYEE_SELECT` に `payee_aliases(id, name)`。`normalizePayeeName`、`findPayeeByName`（プルダウンに出す支払い先＝グループ全体と自分用の非表示でないものから、名前か別名が完全一致するものを探す） |

### 5. 分析・レシート一覧

- `AnalyticsRow.payeeName` → `payeeId`（`null`＝登録外）。集約のキーも支払い先IDにする。`AnalyticsData.payeeNames` → `payees`（`AnalyticsPayee[]`）。`getAnalyticsData` にログインしているユーザーを渡す（見出しの自分用／相方の自分用を決めるため）。
- `DimensionMaster` に `payees` を追加。支払い先の値は支払い先ID（文字列）か `unregistered`。表示名は支払い先の名前／「登録外（手入力）」、色は選択肢の並び順（登録外は内訳なしと同じグレー）。
- 円グラフ・表の並び順は、ほかの項目と同じく金額の大きい順のまま（見出しの順は選択肢だけ）。
- レシート一覧：明細に `payeeId` を追加。URL の `payee` は支払い先IDか `unregistered`。存在しない支払い先・F5 より前の URL（支払い先名）は無視する。空の値を引き継ぐ `keepsEmptyValue` は不要になったため削除した。一覧の画面にも `buildAnalyticsPayees` で作った支払い先（非表示を含むすべて）を渡す。
