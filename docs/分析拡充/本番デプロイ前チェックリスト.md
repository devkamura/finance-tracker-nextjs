## 4. 反映の手順と順番

**DB を先に、アプリを後に反映する。** 新しいアプリは `category_breakdowns` などの新しいテーブルを読むため、DB が古いままだと画面がエラーになる。
F2 で目的・シーンのテーブルを削除するため、**DB を反映してからアプリのデプロイが終わるまでの間は、古いアプリのレシート登録・一覧・詳細がエラーになる**。利用者がいない時間帯に行い、DB の反映後すぐに dev → main のマージ（Vercel のデプロイ）を行う。

- [ ] 本番DBに反映する：`supabase db push --include-seed`
- [ ] `supabase migration list` で今回の分が適用済みになっていることを確認する
- [ ] dev を main にマージする（GitHub で PR）→ Vercel のデプロイが成功したことを「Deployments」で確認する
- [ ] Vercel の環境変数は変更不要であることを確認する（1章のとおり追加の環境変数はない）

## 6. 問題が起きたときの戻し方

- アプリ：Vercel の「Deployments」で1つ前のデプロイを「Promote to Production」（Instant Rollback）で戻す。ただし DB は新しいままなので、メンバーの色は青・赤しか保存できない。
  - **F2 の反映後は、古いアプリには戻せない**（目的・シーンのテーブルがないため、レシートの画面がエラーになる）。アプリの不具合は、新しいアプリを修正して出し直す。
- DB：マイグレーションは自動では戻らない。
  - 新しいテーブル・列は、使わなければ古いアプリの動作に影響しない。基本はアプリだけ戻して、DB は残したまま直す。
  - 交際費を戻す必要がある場合は、カテゴリ「交際費」を作り直し、3.3 で記録した明細IDのカテゴリを交際費に戻す。
  - 目的・シーンを戻す必要がある場合（古いアプリに戻す場合）は、3.1 のバックアップから復元する。
  - それでも直らない場合は 3.1 のバックアップから復元する（反映後に登録されたデータは失われるので、最後の手段にする）。
