## 1. 全体構成

既存構成（Next.js ＋ Supabase）の上に画面を追加する。要件「フロントエンド完結処理」に沿って、処理を次の2段に分ける。

```text
[画面を開いたとき：サーバーで1回だけ]
  ・過去1年分の明細を取得し、按分・税込換算・返金の符号反転を済ませた金額に変換
    （集計に必要な項目＝月・カテゴリ・帰属先・金額だけを渡す）
  ・当月の予算、カテゴリ、メンバー、システム日付（JST）を取得
  → まとめて画面へ渡す（JSON）

[画面を開いている間：画面内だけで処理]
  ・表示対象切替（全体／ユーザー別、共同トグル）、グラフ切替、月・カテゴリ選択
  → 受け取ったデータから再集計して即時描画（サーバー通信なし）

[ドリルダウン：既存のレシート一覧へ移動]
  ・グラフをタップすると、月・カテゴリ・表示対象で絞り込んだレシート一覧へ移動する
  → 一覧はサーバーから取得する（要件の「フィルター遷移」）
```

- 金額の算出は、精算と同じ計算処理を共用する（分析と精算で計算方法がずれないようにするため）。
- 予算の登録・編集だけは、保存のためにサーバー通信を行う。

## 2. 画面設計

### 2.1 画面一覧

| 画面 | 役割 | 区分 |
|---|---|---|
| 予算進捗 | 今月あといくら使えるかを把握する | 新規 |
| 分析 | 過去との比較・使いすぎの深掘り | 新規 |
| 予算設定（管理画面内） | 総予算・カテゴリ別予算を登録・編集する。管理者のみ | 新規 |
| レシート一覧 | ドリルダウンの移動先。カテゴリ・表示対象での絞り込みを追加する | 既存を変更 |
| レシート詳細 | レシート一覧から開く | 既存（変更なし） |

- 予算進捗は別ページとして追加する。現在のホーム（`/`、レシート登録画面）とログイン後の初期表示は変えない（Q7）。
- ヘッダーのナビゲーションに「予算進捗」「分析」を追加する。

### 2.2 画面遷移

ヘッダーのメニューは既存の「一覧」「精算」「管理画面」に、新しく「予算進捗」「分析」の2つを加える。新しい画面への入口とその先の遷移は次のとおり。

| 今いる画面 | 操作 | 移動先 |
|---|---|---|
| どの画面でも | ヘッダーの「予算進捗」 | 予算進捗 |
| どの画面でも | ヘッダーの「分析」 | 分析 |
| 管理画面 | 「予算設定」メニュー（ユーザー管理・支払い先管理と並べる） | 予算設定 |
| 予算進捗 | 「予算を設定」ボタン（管理者にのみ表示） | 予算設定 |
| 予算進捗 | メーター・カテゴリのバーをタップ | レシート一覧（当月 × そのカテゴリ × 表示対象で絞り込み） |
| 分析 | 円グラフの扇・推移グラフの棒をタップ | レシート一覧（その月 × カテゴリ × 表示対象で絞り込み） |
| レシート一覧 | ブラウザの「戻る」 | 元の予算進捗／分析（選択状態を復元） |
| レシート一覧 | 行を開いて「詳細」 | レシート詳細（既存のまま） |
| 予算設定 | 保存・戻る | 管理画面 |

予算進捗・分析の選択状態（表示対象・グラフ種類・月・カテゴリ）は URL に持たせ、レシート一覧から戻ったときに同じ状態で開く。

### 2.3 予算進捗画面

```text
┌────────────────────────────────┐
│ 2026年10月の予算     [全体|A|B] 共同□ │ ← 表示対象・共同トグル
│                                    │
│        ╭───────╮                   │
│       ╱  62%    ╲   ← ドーナツ      │
│      │ 31,000円   │     緑/黄/赤     │
│       ╲ /50,000円╱                  │
│        ╰───────╯                   │
│      あと 19,000円                  │
│   月の経過 6% ／ 予算消化 62%  ⚠     │
├────────────────────────────────┤
│ カテゴリ別（危険度順）               │
│ 食費     ██████████░ 95%  あと 500円 │ 赤
│ 交際費   ██████░░░░ 60%  あと4,000円 │ 黄
│ 日用品   █░░░░░░░░░  8%  あと9,200円 │ 緑
│ 娯楽     予算未設定   支出 1,200円    │
└────────────────────────────────┘
```

- 中心に消化率と「現在支出／予算」、下に「あと〇〇円」を表示する。超過時は「〇〇円オーバー」と表示する。
- カテゴリ別バーは縦に並べ、3.4節の順で自動ソートする。
- 予算未設定のカテゴリはバーを出さず、支出額のみ表示する。
- メーター・各バーをタップすると、当月×該当カテゴリで絞り込んだレシート一覧へ移動する（メーターは全カテゴリ）。
- 管理者には「予算を設定」ボタンを表示し、予算設定画面へ移動できるようにする。一般メンバーには表示しない。
- 予算が未設定の場合、管理者には設定を促す案内を、一般メンバーには「予算は管理者が設定します」と表示する。
- 予算は「全体」にのみ設定する（Q4）。表示対象を A・B に切り替えた場合は、メーター・バーの代わりに当月の支出額（総額・カテゴリ別）だけを表示し、警告色・自動ソートは行わない（カテゴリは金額の大きい順）。

### 2.4 分析画面

```text
┌────────────────────────────────┐
│ 分析                [全体|A|B] 共同□ │
│ [円グラフ | 推移グラフ]              │ ← グラフ種類切替
├────────────────────────────────┤
│ 円グラフ： 月 [2026年9月 ▼]          │
│   カテゴリ別構成比（％と金額）        │
├────────────────────────────────┤
│ 推移グラフ： カテゴリ [総支出 ▼]      │
│   棒：金額（左軸・円）                │
│   線：前月比（右軸・％） ── 100%基準線 │
│   X軸：2025/11 … 2026/10（12か月）   │
└────────────────────────────────┘
```

- 円グラフ：選択月のカテゴリ別支出割合。月は過去12か月から選ぶ。
- 推移グラフ：カテゴリセレクタの選択肢に「総支出」を含め、1系列ずつ切り替えて表示する（Q8）。
- 円グラフの扇・推移グラフの棒をタップすると、該当月（×カテゴリ）で絞り込んだレシート一覧へ移動する。

### 2.5 ドリルダウン（絞り込み付きレシート一覧）

何の支払いで発生した支出かがわかるよう、明細単位ではなく**該当する明細を含むレシートの一覧**を表示する。既存のレシート一覧画面に絞り込みを追加して使う。

```text
2026年9月 ／ 食費 ／ 共同 で絞り込み中   [解除]
食費の合計：2,500円

09/14  スーパー     3,000円   うち食費 2,000円
09/20  コンビニ       500円   うち食費   500円
```

- 絞り込み条件：月・カテゴリ（メーターからの場合は全カテゴリ）・表示対象。条件に当てはまる明細を1件以上含むレシートを表示する。
- 各行はレシートの支払額を表示し、その横に「うち〇〇 〇〇円」と、グラフに計上された分（按分後）を添える。
- 一覧の上部に「うち〜」の合計を表示する。この金額はグラフの値と一致する。
- 行を開いて明細を見たときは、条件に当てはまる明細を強調表示し、それ以外の明細は薄く表示する。
- 絞り込み中であることを上部に表示し、「解除」で通常の月別一覧に戻る。
- 「うち〜」は按分後の金額のため、割引などがあるレシートでは商品の入力金額と一致しない場合がある。
  - 例：明細 食品1,000円・化粧品1,000円、支払額1,500円のレシートは、一覧・詳細では明細が各1,000円（合計2,000円）と表示されるが、集計では各750円（合計1,500円）となる。
  - このずれは**許容する**（2026-10-02 確認済み）。一覧・詳細の明細表示は入力金額のままとし、集計額の併記は行わない。

### 2.6 予算設定画面（管理画面内）

- 既存の管理画面（ユーザー管理・支払い先管理）と同じ並びにメニューを追加する。管理者のみ開ける。

- 月（初期値は当月）を選び、全体の総予算とカテゴリ別予算を入力する（表示対象の選択はない）。
- 予算を設定するカテゴリは任意（すべてのカテゴリに入力する必要はない）。
- カテゴリ別予算の合計が総予算を超える場合は保存できない。
- 画面に「未割当：〇〇円（予算を設定していないカテゴリ用）」＝総予算 − カテゴリ別予算の合計 を表示する。
- 「先月の予算をコピー」操作を設ける。

## 3. 業務ロジック

### 3.1 集計対象の金額

精算と同じ計算で、明細ごとの金額を求める。

1. **税込換算**：税別の明細は税率を掛けて税込にする（1円未満切り捨て）。
2. **按分**：レシートの支払額を、明細の税込金額の比率で配分する。端数は金額の大きい明細から1円ずつ配る。明細の合計は必ず支払額と一致する。
3. **返金**：取引種別が「返金」のレシートはマイナスで計上する。
4. 明細の合計が0円のレシートは、集計に影響させない。

### 3.2 表示対象（全体／ユーザー別）

| 表示対象 | 集計する明細 | 共同トグル |
|---|---|---|
| 全体 | すべての明細（共同＋A＋B） | なし |
| ユーザー別（A・B） | 帰属先がそのユーザーの明細 | オンで帰属先「共同」の明細の**1/2**も含める |

- 支払者ではなく帰属先で振り分ける。支払者が相方のレシートでも、自分が帰属先の明細があれば集計に含め、ドリルダウンの一覧にもそのレシートを表示する。
- 共同トグルは、ユーザー別のときだけ表示する。初期値は**オフ**。
- 共同分を1/2とすることで、トグルオン時の「A＋B」は「全体」と一致し、精算の負担額と同じ考え方になる。
- 相方のユーザー別表示も見られる（お互いの支出を把握するため）。
- 「共同のみ」の表示は設けない。要件定義書の「ユーザー個別と共同の切り替え」の「共同」は、本書の「全体」を指す。

### 3.3 期間・日付

- 月は暦月とし、JST で判定する。
- 「過去1年間」＝当月を含む12か月とする（例：当月が2026年10月なら、2025年11月〜2026年10月）。取得範囲と表示範囲は同じ12か月にそろえる（既存のデータ保持方針「当月から遡って12か月」と一致させるため）。
- 「システム日付」はサーバーの JST 日付を使い、端末の時計には依存させない。

### 3.4 予算アラート・自動ソート

```text
消化率 = 当月の支出額 ÷ 予算額
経過率 = 今日の日 ÷ 当月の日数        （例：10月2日 → 2 ÷ 31 ≒ 6.5%）

状態  = 消化率 > 100%         → 予算超過（赤）
      = 消化率 > 経過率        → ペース超過（黄）
      = それ以外              → 正常（緑）
```

- 要件の「赤（または黄色）」は、予算超過＝赤、ペース超過＝黄の2段階とする（Q6）。
- 予算が0円または未設定のカテゴリは判定の対象外とする。
- 自動ソート：予算超過 → ペース超過 → 正常 の順に並べる。同じ状態の中では「消化率 − 経過率」の大きい順にする。

### 3.5 前月比

- 前月比 ＝ 当月の金額 ÷ 前月の金額 × 100（％）。
- 前月が0円以下の場合は算出しない（折れ線を途切れさせる）。
- 12か月のうち最も古い月（左端）は前月のデータがないため算出せず、折れ線はその翌月から始める。グラフに「前月データなし」と注記する。
- 当月も前月比を表示する。月の途中の金額で計算される旨をグラフに注記する（Q8）。

### 3.6 予算の持ち方

- 予算は「月 × （総予算 または カテゴリ）」ごとに金額を持つ。表示対象は「全体」のみ（Q4）。
- 将来ユーザー別（A・B）の予算を追加する可能性があるため、データには表示対象の項目を持たせておき、今回は「全体」だけを使う。
- その月の予算が未登録の場合は、直近の過去の月の予算を自動で引き継いで表示し、「先月の予算を表示中」と明記する（Q5）。
- カテゴリ別予算の合計は総予算以下とする。総予算との差額は「未割当」（予算を設定していないカテゴリ用の枠）として扱う（Q5-2）。
- 総予算メーターは、総支出（予算を設定していないカテゴリの支出も含む）と総予算で比べる。

### 3.7 返金でマイナスになった場合の表示

返金は返金を受けた月にマイナスとして常に集計に含める（含める／含めないの切り替えは設けない）。ひと月の中で返金が支出を上回り、カテゴリや月の金額がマイナスになった場合は次のとおり扱う。

- **描画のみ0扱い**：円グラフの扇、推移グラフの棒、予算進捗のバーは0として描く。
- **数字・計算は実際の金額**：凡例・ラベル・合計・残額・前月比・ドリルダウンの合計は、マイナスのまま表示・計算する。
- **円グラフの％**：返金を差し引いた後にプラスになっているカテゴリの合計を分母にする（返金そのものを除外するのではなく、差し引いた結果マイナスになったカテゴリだけを円から外す）。
- **注意書き（必須）**：マイナスのカテゴリ・月がある場合は、必ずグラフの近くに注意書きを表示する。
  - 共通：「返金が支出を上回ったカテゴリは、グラフ上0として表示しています（〇〇 −8,000円）」
  - 円グラフ：上記に加えて「割合は、マイナスのカテゴリを除いた合計（38,000円）に対する値です。実際の合計は30,000円です」

円グラフの分母の例（9月：食費の返金2,000円、衣類の返品8,000円がある場合）

| カテゴリ | 支出 | 返金 | 差し引き（実際の金額） | 円グラフで描く値 |
|---|---|---|---|---|
| 食費 | 30,000円 | −2,000円 | 28,000円 | 28,000円 |
| 日用品 | 10,000円 | ― | 10,000円 | 10,000円 |
| 衣類・ファッション | ― | −8,000円 | −8,000円 | 0円（描かない） |
| 合計 | 40,000円 | −10,000円 | 30,000円（表示する合計） | 38,000円（％の分母） |

→ 食費 74%（28,000 ÷ 38,000）、日用品 26%。返金のない月、または全カテゴリがプラスの月は、分母と合計が一致する。

表示の例：9月に食費30,000円・日用品10,000円・衣類−8,000円（8月購入の服を9月に返品）の場合

| 場所 | 描画 | 表示する数字 |
|---|---|---|
| 円グラフ | 衣類の扇は描かない | 凡例「衣類・ファッション −8,000円」、合計 32,000円、食費75%・日用品25% |
| 推移グラフ | マイナスの月は高さ0 | ラベルは実際の金額 |
| 予算進捗 | 衣類のバーは0% | 「−8,000円」「あと 18,000円」（予算10,000円の場合） |

## 4. データ設計

### 4.1 既存データ（変更なし）

レシート（支払者・支払額・取引種別・日時）、明細（金額・税区分・税率・カテゴリ・帰属先）、税率、カテゴリを参照のみで使う。既存テーブルの変更はない。

### 4.2 新規：予算

| 項目 | 説明 |
|---|---|
| グループ | どのグループの予算か |
| 対象月 | 月単位 |
| 表示対象 | 今回は「全体」のみ。将来のユーザー別予算に備えて項目だけ用意する |
| カテゴリ | 空＝総予算、指定あり＝カテゴリ別予算 |
| 予算額 | 0円以上の整数（円） |
| 登録者・更新者・日時 | 監査用 |

- 同じ「グループ × 月 × 表示対象 × カテゴリ」の予算は1件だけとする。
- 参照はグループのメンバー全員、登録・編集は管理者のみ（画面側だけでなくデータ側の権限でも制限する）。

## 5. 非機能要件

| 観点 | 方針 |
|---|---|
| 応答性 | 画面を開いた後の操作は画面内の再計算のみで、即時（ミリ秒単位）に反映する |
| 初回表示 | 1年分の明細（想定：年間約4,400件）を一括で受け取る。集計に必要な項目（月・カテゴリ・帰属先・金額）だけに絞り、商品名・支払い先などはドリルダウン先の一覧で取得する |
| データ件数 | 1年分の明細が DB の1回の取得上限（1,000件）を超えても、漏れなく取得できること |
| セキュリティ | 他グループの明細・予算は取得できないこと（既存の行レベル権限に従う） |
| アクセシビリティ | 状態を色だけで伝えず、アイコンと文言（「ペース超過」「予算オーバー」）も併記する |
| グラフ描画 | グラフ描画ライブラリ Recharts を新規に導入する（Q9） |

## 6. テスト観点（概要）

詳細は docs/test-spec.md に追記する。

自動テストは単体・結合（Vitest）までとし、**E2Eテストは実施しない**（この開発環境では Playwright のブラウザを導入できないため。既存機能と同じ扱い）。画面操作でしか確かめられない観点（下記の【手動】）は、test-spec.md に E2E 項目として残したうえで、手動で確認する。

- 金額算出：按分後の合計が支払額と一致する、税別の換算、返金のマイナス計上
- 返金でマイナスになったカテゴリ：描画は0、数字・合計・残額は実際の金額、円グラフの％の分母（返金差し引き後のプラスのカテゴリ合計）、注意書きが必ず表示されること（マイナスがない月は表示されないこと）
- 表示対象の振り分け、月別・カテゴリ別集計
- 経過率（月末・うるう年2月）、アラート3状態の境界値、危険度ソート
- 前月比（前月0円のとき算出しない）
- JST の月境界（9/30 23:59 と 10/1 0:00）
- 1,000件を超える明細の取得、他グループのデータが見えないこと
- 予算：管理者のみ登録・編集でき、一般メンバーは画面・データの両方で編集できないこと
- 予算：カテゴリ別の合計が総予算を超えると保存できないこと、未割当額の計算、前月予算の引き継ぎ
- 【手動】画面操作中にサーバー通信が発生しないこと
- ドリルダウン：絞り込み一覧の「うち〜」合計がグラフの値と一致すること、複数カテゴリが混ざったレシートの表示、【手動】戻ったときに選択状態が復元されること
- 絞り込みを使わない従来の一覧表示が変わらないこと（リグレッション）

## 7. 既存機能への影響

- 精算：計算処理を分析と共用するが、精算結果は変わらない（既存テストで担保する）。
- ヘッダーのナビゲーションにリンクを追加する。
- メンバーの色：12色から2色（ブルー／レッド）に変更する。グラフのカテゴリの色と紛れないようにするため（2026-10-03 追加決定）。
- レシート一覧：カテゴリ・表示対象での絞り込み、「うち〜」金額、該当明細の強調表示、絞り込み表示と解除を追加する。絞り込みなしで開いた場合の表示・動作は変えない。
- 既存文書の改訂：Q1 が確定したら、「支出分析は按分後の金額を使う」に改める。
- DB：予算テーブルを追加する。既存テーブルは変更しない。
