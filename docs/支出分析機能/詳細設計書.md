### 3. 月の計算（`lib/analytics/months.ts`）

月・日は JST で判定する（基本設計書3.3節）。サーバーは `instrumentation.ts` で起動時に `TZ=Asia/Tokyo` に固定されているため、既存のレシート一覧・精算（`lib/receipts/queries.ts` の `monthPeriod`）と同じく、`getFullYear()`・`getMonth()`・`getDate()` で JST の値が得られる。既存と同じ書き方にそろえることで、同じレシートが一覧・精算と分析で別の月に入ることを防ぐ。

日付の計算はすべてサーバー側で行い、ブラウザには `"YYYY-MM"`・`"YYYY-MM-DD"` の文字列だけを渡す（ブラウザの時計・タイムゾーンには依存しない）。

| 関数 | 内容 | 例 |
|---|---|---|
| `todayKey(now: Date)` | 今日を `"YYYY-MM-DD"` で返す | `"2026-10-03"` |
| `monthKeyOf(date: Date)` | その時刻が属する月を `"YYYY-MM"` で返す | `"2026-09"` |
| `lastTwelveMonths(today)` | 当月を含む12か月を古い順に返す | `"2026-10-03"` → `["2025-11", …, "2026-10"]` |
| `monthRange(months)` | 12か月の取得範囲 [最初の月の1日0時, 最後の月の翌月1日0時) を返す | `["2025-11"…"2026-10"]` → [2025-11-01, 2026-11-01) |
| `addMonths(monthKey, n)` | 月キーをずらす | `("2026-01", -1)` → `"2025-12"` |

### 4. データ取得（`lib/analytics/queries.ts`）

#### 4.1 取得

```text
getAnalyticsData(supabase, groupId, now = new Date())
  today      = todayKey(now)
  months     = lastTwelveMonths(today)
  [from, to) = monthRange(months)
  receipts を occurred_at ∈ [from, to) で取得
    select: id, occurred_at, amount, payer_user_id, transaction_types(name),
            receipt_details(price, tax_type, category_id, owner_user_id, consumption_taxes(multiplier))
    order:  occurred_at, id
    1,000件ずつ range() で取得し、1,000件未満が返ったら終了
  members    = getGroupMembers()（既存）
  categories = categories を id 順に取得
```

- `supabase/config.toml` の `max_rows = 1000` はレシート（親）の件数に効く。明細（子）は各レシートにまとめて付いてくる。
- 取得エラー時は例外を投げる（既存ページと同じく Next.js のエラー画面に任せる）。

#### 4.2 変換と集約

1. レシートごとに、精算と同じ `allocateReceiptAmount` で支払額を明細に按分する（税込換算・最大剰余法を含む）。
2. 取引種別が「返金」なら、按分結果をマイナスにする。
3. 明細を **「月 × カテゴリ × 帰属先」ごとに合計して** 画面に渡す（確認事項1）。

```ts
// lib/analytics/types.ts
type AnalyticsRow = {
  month: string;              // "2026-09"
  categoryId: number;
  ownerUserId: string | null; // null＝共同
  amount: number;             // 按分・符号反転済みの合計（円、整数）
};

type AnalyticsData = {
  today: string;              // "2026-10-03"
  months: string[];           // 12か月（古い順）
  categories: { id: number; name: string }[];
  members: { userId: string; displayName: string; color: string | null }[];
  rows: AnalyticsRow[];
};
```

### 5. 集計ロジック（`lib/analytics/aggregate.ts`）

#### 5.1 表示対象

```ts
type Scope = { kind: "all" } | { kind: "user"; userId: string; includeJoint: boolean };
```

| 表示対象 | 対象の行 | 重み |
|---|---|---|
| 全体 | すべて | 1 |
| ユーザー（共同トグルオフ） | `ownerUserId === userId` | 1 |
| ユーザー（共同トグルオン） | 上記＋`ownerUserId === null` | 共同は 0.5 |

#### 5.2 カテゴリ別集計と端数

- `sumByCategory(rows, scope, month)`：カテゴリごとに合計する。
- 共同の1/2で出る0.5円は**丸めずにそのまま扱う**（確認事項2）。端数は .5 だけで、整数を2で割った値の和なので浮動小数点の誤差は出ない。
- 「A＋B＝全体」「内訳の合計＝表示する合計」が常に成り立つ。
- 表示：小数があるときは小数第1位まで（`8,500.5円`）、整数のときは小数なし（`5,200円`）。
- .5 が出るのはユーザー別表示で共同トグルがオンのときだけ。予算進捗（フェーズ5）は予算が全体のみのため .5 は出ない。ユーザー別予算を追加するときは、.5 と予算の比較方法を改めて検討する。

#### 5.3 円グラフ用データ

`buildPieData(categorySums)` は次を返す。

| 項目 | 内容 |
|---|---|
| `slices` | 金額がプラスのカテゴリ（金額の大きい順）。各カテゴリの `percent` は `amount ÷ positiveTotal × 100` を小数第1位で四捨五入 |
| `negatives` | 金額がマイナスのカテゴリ（注意書き用） |
| `zeroCategories` | 対象の行はあるが合計が0円のカテゴリ（表には出す） |
| `total` | 実際の合計（マイナスも含む） |
| `positiveTotal` | ％の分母（プラスのカテゴリの合計） |

- 明細が1件もない月：`slices` は空、`total` は0。画面には「この月の支出はありません」と表示する。
- プラスのカテゴリがない（すべて返金など）月：円グラフは描かず、表と注意書きだけを出す。

### 6. 画面（`/analytics`）

#### 6.1 構成

```text
分析
[全体|A|B]  □共同を含める        ← Bを選ぶと「□共同を含める」が出る
◀ 2026年9月 ▼ ▶                  ← 月の選択（過去12か月）
┌──────────────────────┐
│       （円グラフ）         │
│     合計 30,000円          │
└──────────────────────┘
⚠ 返金が支出を上回ったカテゴリは、グラフ上0として表示しています（衣類・ファッション −8,000円）。
  割合は、マイナスのカテゴリを除いた合計（38,000円）に対する値です。実際の合計は30,000円です。
┌──────────────────────┐
│ ● 食費        74.0%  28,000円 │
│ ● 日用品      26.0%  10,000円 │
│   衣類・ファッション  ―  −8,000円 │
└──────────────────────┘
```

- 表示対象のボタンは、メンバーの表示名（`UserBadge` と同じ色）で出す。メンバーが1人のグループでは「全体」と本人だけになる。
- 共同トグルはユーザーを選んだときだけ表示する。初期値はオフ。全体に戻すとトグルは隠れる（値はオフに戻す）。
- 月の選択は既存の `MonthSelector` と同じ見た目（◀ ▼ ▶）にする。ただし `MonthSelector` は URL 遷移（サーバー通信）を行うため使わず、画面内の状態だけを変える専用部品を作る。初期値は当月。
- 円グラフの扇はカテゴリの色で塗り、凡例の代わりに下の内訳表を使う。扇にマウスを乗せる（タップする）とカテゴリ名・金額・％を出す。
- 金額表記は既存画面に合わせて `toLocaleString()` ＋「円」。マイナスは `−8,000円`。

#### 6.2 状態と URL

- 状態：`scope`（全体 または ユーザーID）、`joint`（共同トグル）、`month`（"YYYY-MM"）。
- 初期状態はサーバー側で `searchParams` から読み、Client Component に props で渡す。不正な値は初期値（全体・オフ・当月）に戻す。
- 操作のたびに `window.history.replaceState` で URL を書き換える（例：`/analytics?scope=<userId>&joint=1&month=2026-09`）。Next.js のドキュメント上、`replaceState` はルーターと連携し、ページの再取得は起きない。
- `pushState` ではなく `replaceState` にする理由：操作ごとに履歴が増えると、ブラウザの「戻る」で切り替え操作を1つずつ巻き戻すことになるため（確認事項3）。この URL はフェーズ3で、レシート一覧から戻ったときの状態復元に使う。

#### 6.3 カテゴリの色（`lib/analytics/category-colors.ts`）

カテゴリ ID 順に12色の固定パレットを割り当て、13番目以降は先頭から繰り返す（色の重複は許容）。同じカテゴリは月や表示対象を変えても常に同じ色になる（確認事項4）。

メンバーの色（ブルー／レッド、6.5節）・共同の色（濃いグレー）と紛れないよう、青系・赤系・グレーを除いた12色にする。

| 2 | アンバー | `#f59e0b` |

#### 6.5 メンバーの色を2色に変更（既存機能の変更）

| 項目 | 内容 |
|---|---|
| 選べる色 | ブルー（`blue`）・レッド（`red`）の2色と「未設定」。既存のバッジの配色（`bg-blue-100` など）はそのまま使う |

| DB | マイグレーションで、①ブルー・レッド以外の `profiles.color` を null に更新 ②`color` の check 制約を `color is null or color in ('blue', 'red')` に置き換える |
| 共同の色 | 濃いグレー（変更なし） |


#### 6.4 注意書き（`NegativeAmountNotice`）

- `negatives` が1件以上あるときだけ表示する（基本設計書3.7節）。
- 1行目：「返金が支出を上回ったカテゴリは、グラフ上0として表示しています（カテゴリ名 金額、…）」
- 2行目（円グラフを描いているときのみ）：「割合は、マイナスのカテゴリを除いた合計（positiveTotal円）に対する値です。実際の合計はtotal円です」

### 9. 確認事項

| No | 論点 | 提案 |
|---|---|---|
| 1 | 画面に渡すデータの粒度 | **確定**：「月×カテゴリ×帰属先」の合計にして渡す（最大 12×13×3＝468行）。要件の「全明細データを一括取得」は、集計に必要なデータを初回にまとめて受け取り以降は通信しない、という意図として扱う |
| 2 | 共同1/2で出る0.5円 | **確定**：丸めずに .5 のまま表示する（`8,500.5円`、整数のときは小数なし）。分析は金銭のやり取りではないため整数にそろえる必要がない |
| 3 | 切り替えと「戻る」 | **確定**：切り替えは履歴に積まない（`replaceState`）。「戻る」1回で分析画面に来る前の画面へ戻る |
| 4 | カテゴリの色 | **確定**：カテゴリ ID 順の固定12色（青系・赤系・グレーを除く）。13番目以降は重複を許容する |
| 5 | メンバーの色 | **確定**：ブルー／レッドの2色に変更。既存の他の色は未設定に戻す。同じ色を選んでもよい。このフェーズに含める |
