# 実装計画（支出分析機能）

対象：[基本設計書.md](./基本設計書.md)（2026-10-03 確定）

大規模な追加になるため、画面で触れる単位にフェーズを分けて進める。

## 進め方

各フェーズで次を繰り返し、ユーザーのOKが出たら次のフェーズへ進む。

1. そのフェーズの詳細設計と `docs/test-spec.md` のテスト項目を書き、確認をもらう
2. 実装と単体・結合テスト（Vitest）
3. ユーザーが画面で触って確認 → 指摘があれば修正

E2Eテストは環境の制約により実施しない（画面操作の観点は手動で確認する）。

## ブランチ・PR

| ブランチ | 役割 |
|---|---|
| `main` | 本番。**全体が完成するまで触らない** |
| `dev` | main のコピー。各フェーズのブランチはここから切り、完成したらここへマージする |
| `feature-iNNNN-xxx` | フェーズごとの開発ブランチ（xxx は内容を端的に表す名前） |

| ブランチ | 対象 | 状態 |
|---|---|---|
| `feature-i0001-design-docs` | 要件定義・基本設計・実装計画 | 作業中 |
| `feature-i0002-analytics-pie` | フェーズ0（土台）＋1（円グラフ） | 未着手 |
| `feature-i0003-analytics-trend` | フェーズ2（推移グラフ） | 未着手 |
| `feature-i0004-receipt-filter` | フェーズ3（レシート一覧への絞り込み） | 未着手 |
| `feature-i0005-budget-settings` | フェーズ4（予算設定） | 未着手 |
| `feature-i0006-budget-progress` | フェーズ5（予算進捗） | 未着手 |
| `feature-i0007-final-check` | フェーズ6（全体の確認・文書の改訂） | 未着手 |

- 各フェーズは、ユーザーが画面で確認してOKが出たら、GitHub で `dev` 向けの PR を作ってマージする。
- 全フェーズ完了後に `dev` → `main` の PR を作成する。

## 詳細設計

- 全体を一度に書かず、各フェーズの開始時にそのフェーズ分を `詳細設計書.md` に追記する。
