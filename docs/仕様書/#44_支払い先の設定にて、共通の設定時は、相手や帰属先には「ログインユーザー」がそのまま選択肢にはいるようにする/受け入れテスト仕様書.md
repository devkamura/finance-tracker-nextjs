# 支払い先の既定値「登録する人」 受け入れテスト仕様書（Issue #44）

対象：[要件定義書.md](./要件定義書.md)。
[docs/test-spec.md](../../test-spec.md) の PR-M-01〜PR-M-04 を、画面で1つずつ確かめられる形にしたもの。

## 前提

- ローカル環境（Supabase ＋ `npm run dev`）で、ゆうき・ふみの2人のアカウントで確認する（ブラウザを分けるか、シークレットウィンドウを使う）。
- マイグレーションを当てておく（`supabase migration up`）。
- ダミーデータは不要。確認用の支払い先は AT-01 で画面から登録し、最後に削除する。
- 確認で登録したレシートは、確認が終わったら削除する（支払い先を削除できるようにするため）。

### 確認用の支払い先（AT-01 で登録する）

| 項目 | 値 |
|---|---|
| 名前 | 登録する人テスト |
| カテゴリ | 食費 |
| 相手 | 登録する人 |
| 帰属先 | 登録する人 |

## 確認項目

| No | 操作 | 期待結果 | 結果 |
|---|---|---|---|
| AT-01 | ゆうきでログインし、設定 ＞ 支払い先で「追加」を押す。相手・帰属先のプルダウンを開く | どちらも「設定しない」の次に「登録する人」がある（帰属先は「設定しない」「登録する人」「共同」「ゆうき」「ふみ」の順） | |
| AT-02 | 上の「確認用の支払い先」の内容で保存し、一覧の行を見る | 既定値の説明が「食費／登録する人／登録する人」、バッジは［👥 共通］ | |
| AT-03 | ゆうきで登録画面を開き、支払い先に「登録する人テスト」を選ぶ | 明細のカテゴリ＝食費、相手＝「自分（ゆうき）」、帰属先＝「ゆうき」が入る | |
| AT-04 | AT-03 のまま「項目を追加」で明細を増やす | 追加した明細にも、相手＝「自分（ゆうき）」、帰属先＝「ゆうき」が入る | |
| AT-05 | 金額を入れて登録し、詳細を開く | 相手・帰属先が「ゆうき」で保存されている（「登録する人」とは出ない） | |
| AT-06 | ふみでログインし、登録画面で支払い先に「登録する人テスト」を選ぶ | 相手＝「自分（ふみ）」、帰属先＝「ふみ」が入る（ふみは自分用の既定値を作っていない） | |
| AT-07 | ふみで画像読み取りを使い、店名が「登録する人テスト」と読める（または読み取り後に支払い先で選ぶ）レシートで確認する ※画像が用意できなければ省略可 | AT-06 と同じく、相手・帰属先にふみが入る | |
| AT-08 | ふみで設定 ＞ 支払い先の「登録する人テスト」の ✏️ を押し、「自分用にする」を押す | 相手＝「自分（ふみ）」、帰属先＝「ふみ」に置き換わってコピーされる。相手・帰属先のプルダウンに「登録する人」は出ない。下に「共通：食費／登録する人／登録する人」が出る | |
| AT-09 | AT-08 のまま「共通に戻す」を押す | 相手・帰属先が「登録する人」に戻り、プルダウンにも「登録する人」が出る。保存しないで閉じる | |
| AT-10 | ふみで設定 ＞ 相手 を開き、「ふみ」を非表示にする。登録画面で「登録する人テスト」を選ぶ | 相手は空欄（「選択してください」の状態）、帰属先は「ふみ」、カテゴリは食費が入る。確認後、「ふみ」を表示に戻す | |
| AT-11 | ゆうきで設定 ＞ 支払い先の「登録する人テスト」を編集し、帰属先を「共同」に変えて保存する。続けてふみで登録画面を開き、同じ支払い先を選ぶ | 一覧の説明が「食費／登録する人／共同」になる。ふみの明細は相手＝「自分（ふみ）」、帰属先＝「共同」 | |
| AT-12 | 既存の支払い先（「登録する人」を使っていないもの）を登録画面で選ぶ | 今までどおりの既定値が入る（変わらない） | |
| AT-13 | スマホ幅（375px）で設定 ＞ 支払い先の編集欄を開く | 「登録する人」を含むプルダウンが押しやすく、横スクロールが出ない | |
| AT-14 | 後片付け：AT-05 などで登録したレシートを削除し、「登録する人テスト」を削除する | 削除できる（使用中でなくなるため） | |
