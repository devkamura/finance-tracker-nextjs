# 詳細設計書：支払い先の既定値「登録する人」（Issue #44）

対象：[要件定義書.md](./要件定義書.md)
ブランチ：`feature-i0016-payee-registrant`（dev から作成）
関連：[docs/全体仕様書/基本設計書.md](../../全体仕様書/基本設計書.md) 3.6節・5.3節（共通の既定値・自分用の既定値の仕組み）

## 1. 方針

支払い先の既定値（`PayeeDefaults`）は、明細と同じ形の文字列で相手（`counterpartId`）・帰属先（`ownerUserId`）を持っている。帰属先の「共同」を `OWNER_JOINT_VALUE`（`"joint"`）で表しているのと同じように、「登録する人」を新しいセンチネル値 `REGISTRANT_VALUE`（`"registrant"`）で表す。

置き換えは**既定値を明細に入れる直前**に、純粋関数 `resolveRegistrantDefaults` で行う。置き換えたあとの既定値は今までの既定値と同じ形なので、明細への反映（`applyPayeeDefaults`）・非表示の相手を入れないルール・保存の処理は変えずに使える。

| 層 | 「登録する人」の持ち方 |
|---|---|
| DB（payees） | `default_counterpart_registrant`・`default_owner_registrant` = true |
| 画面・Server Action（`PayeeDefaults`） | `counterpartId`・`ownerUserId` = `REGISTRANT_VALUE` |
| 明細（`ReceiptItem`）・レシート | 持たない（本人の相手 id・user id に置き換え済み） |

## 2. DB

マイグレーション：`supabase/migrations/20261126000001_payee_registrant_defaults.sql`

```sql
alter table public.payees
  add column default_counterpart_registrant boolean not null default false,
  add column default_owner_registrant boolean not null default false,
  add constraint payees_default_counterpart_registrant_check
    check (not (default_counterpart_registrant and default_counterpart_id is not null)),
  add constraint payees_default_owner_registrant_check
    check (not (default_owner_registrant
                and (default_owner_joint or default_owner_user_id is not null)));
```

- 既存の支払い先はすべて false（今までの既定値のまま。要件 7）。
- 自分用の既定値（`payee_member_defaults`）では選べないため、列を足さない（要件 2 を DB の形でも保証する）。
- RLS・トリガー（`check_payee_defaults`）は変更しない。フラグはグループのデータを参照しないため、整合性の確認は不要。
- `lib/supabase/database.types.ts` の `payees`（Row・Insert・Update）に2列を追加する。

## 3. 定数（`lib/constants.ts`）

| 定数 | 値 | 用途 |
|---|---|---|
| `REGISTRANT_VALUE` | `"registrant"` | 既定値の相手・帰属先＝登録する人 |
| `REGISTRANT_LABEL` | `"登録する人"` | プルダウン・一覧の説明の表示名 |

## 4. 業務ロジック（`lib/receipts/payees.ts`）

| 関数 | 変更 |
|---|---|
| `PAYEE_SELECT` | payees の2列（`default_counterpart_registrant, default_owner_registrant`）を読む。自分用の既定値の select は変えない |
| `toDefaults`（`toPayee` の中） | フラグが true なら `REGISTRANT_VALUE` にする。フラグがない行（自分用の既定値）は今までどおり |
| `toPayeeDefaultColumns` | 返す列は今までと同じ（payees・payee_member_defaults 共通）。`REGISTRANT_VALUE` は相手・帰属先の列では null／false にする |
| `toPayeeCommonDefaultColumns`（新規） | `toPayeeDefaultColumns` に2つのフラグを足す。共通の既定値（payees）の保存で使う |
| `resolveRegistrantDefaults`（新規） | 下記 |
| `describePayeeDefaults` | 相手・帰属先が `REGISTRANT_VALUE` なら「登録する人」と出す（要件 6） |
| `validatePayeeDefaults` | 4つ目の引数 `{ allowRegistrant }` を追加。false（既定）なら `REGISTRANT_VALUE` は「相手（帰属先）の既定値が不正です。」。true なら相手の存在・メンバーの確認を飛ばす |

### 4.1 `resolveRegistrantDefaults(defaults, currentUserId, counterparts)`

| 項目 | 置き換え |
|---|---|
| 相手 | `kind === "member"` かつ `userId === currentUserId` かつ表示中の相手の id。なければ空欄（要件 5） |
| 帰属先 | `currentUserId` |
| 操作している人が不明（`currentUserId` が undefined） | どちらも空欄 |
| 「登録する人」でない値 | そのまま。どちらも「登録する人」でなければ、受け取った既定値をそのまま返す |

非表示の相手を空欄にするのは `applyPayeeDefaults` でも行っているが、「自分用にする」でのコピー（4.3 節）でも同じ結果にするため、ここでも空欄にする。

## 5. Server Action（`lib/actions/settings/payees.ts`）

| 関数 | 変更 |
|---|---|
| `checkDefaults` | 引数を `{ common, current }` にし、`validatePayeeDefaults` に `allowRegistrant: common` を渡す |
| `createPayee` | `common: true`。保存は `toPayeeCommonDefaultColumns` |
| `updatePayeeCommonDefaults` | `common: true`。保存は `toPayeeCommonDefaultColumns` |
| `setOwnPayeeDefaults` | `common: false`（「登録する人」はエラー。DB には書き込まない）。保存は今までどおり `toPayeeDefaultColumns` |

## 6. 画面

### 6.1 設定 ＞ 支払い先（`components/settings/PayeeSettingsManager.tsx`）

- 編集欄（`PayeeEditor`）の相手・帰属先のプルダウンで、共通の既定値を編集しているとき（`!draft.own`。追加欄も含む）だけ、「設定しない」の次に「登録する人」を出す。
- 「自分用にする」：`resolveRegistrantDefaults(defaults, currentUserId, counterparts)` を通してから自分用の編集に切り替える（要件 3）。「共通に戻す」は今までどおり共通の既定値（「登録する人」のまま）を表示し直す。
- 一覧の既定値の説明・「共通：…」は `describePayeeDefaults` を使っているため、変更なしで「登録する人」と出る。

### 6.2 レシート登録・編集（`components/receipt-form/ReceiptForm.tsx`）

- `withPayeeDefaults`：`payeeDefaultsFor`（自分用があれば自分用、なければ共通）の結果を `resolveRegistrantDefaults` に通してから `applyPayeeDefaults` に渡す。
- 支払い先の選択・明細の追加・画像読み取り（`applyOcrPatch`）は、すべて `withPayeeDefaults` を通るため、この1か所の変更で要件 4 を満たす。
- 置き換えは画面の中だけで行い、サーバーへの通信は増やさない（相手の一覧は画面を開いたときに取得済み）。

## 8. 既知の制約

| 内容 | 影響 | 対応案 |
|---|---|---|
| 共通の既定値が「登録する人」のとき、自分用の既定値を作ると本人の値に固定される | 自分用では「登録する人」に戻せない（「共通に戻す」で戻す） | 本人を選ぶのと同じ結果なので、対応しない |
| 本人が自分の相手を非表示にしていると、相手は空欄になる | 相手を手で選び直す | 要件 5 のとおり（今のルールに統一） |
