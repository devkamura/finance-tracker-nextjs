# 詳細設計書：特別費フラグ（Issue #41）

対象：[要件定義書.md](./要件定義書.md)
ブランチ：`feature-i0015-special-expense`（dev から作成）

## 1. 方針

分析の「絞り込み」「分ける」とレシート一覧への絞り込みは、項目（`DIMENSIONS`）と条件（`Conditions`）の仕組みを共通で使っている（`lib/analytics/dimensions.ts`）。
特別費はこの項目の1つ（`specialExpense`）として追加し、「特別費を含める」が OFF のときは**条件に `specialExpense: "normal"` を足す**ことで実現する。

こうすると、円グラフ・推移グラフ・一覧への絞り込み（「うち〇〇円」）がすべて同じ `matchesConditions` を通るため、グラフと一覧の金額が一致する仕組みをそのまま使える。精算（`lib/settlement`）はこの仕組みを使っていないため、影響を受けない。

## 2. DB

マイグレーション：`supabase/migrations/20261125000001_receipt_detail_special_expense.sql`

```sql
alter table public.receipt_details
  add column is_special_expense boolean not null default false;
```

- 既存の明細はすべて false（通常）になる。
- RLS・トリガー・精算の RPC は変更しない。確定済みの月の書き込み禁止（RLS）はそのまま効く（要件 8）。
- `lib/supabase/database.types.ts` の `receipt_details` に `is_special_expense` を追加する。

## 4. 登録・編集画面

### 4.1 フォームの状態（`components/receipt-form/ReceiptForm.tsx`）

- `createEmptyItem`・`buildOcrItem`：`isSpecialExpense: false`。
- 明細の追加（`addItem`）：追加する明細は常に false（チェックなし）。
- 一括入力（`BulkInputModal`）：最後に「特別費」のプルダウン（変更しない／特別費にする／特別費にしない。初期値：変更しない）を置く。「特別費にする」は `BulkInputValues.isSpecialExpense = true`、「特別費にしない」は `false` を渡して全明細を変える。「変更しない」は `undefined`（各明細の値のまま。帰属先などだけを一括入力したときに特別費が外れないようにするため）。適用後は「変更しない」に戻す。
- 一括入力の1項目への反映は、純粋関数 `applyBulkInput(item, values, breakdowns)`（`ReceiptForm.tsx` から export）にまとめて単体テストする。
- 支払い先の既定値（`applyPayeeDefaults`）・OCR の反映は `isSpecialExpense` を変えない（`...item` で引き継ぐ）。
- 2026-11-25 変更：当初は項目の欄に一括チェック（全明細が特別費のとき ON の表示）を置いていたが、ユーザーの指示で一括入力へ移した。
- 複製登録（`buildPartnerItems`）は `...item` でコピーするため、フラグも引き継がれる。

### 4.2 画面

- `ReceiptItemCard`：開いたときの欄の最後に「特別費」チェックボックスを置く。タグのボタンと続けて見えないよう、上に区切り線を入れる。閉じているときのサマリーにも「・特別費」を足す。

### 4.3 保存（`lib/receipts/shared.ts`）

- `buildReceiptDetailRows`：`is_special_expense: item.isSpecialExpense === true`。クライアントから来る JSON の値が boolean 以外（未指定を含む）のときは false として扱う。
- 入力チェック（`validateReceiptForm`）は変更しない（必須の項目ではないため）。

### 4.4 編集画面の初期値（`lib/receipts/queries.ts`）

- 編集用の取得で `is_special_expense` を読み、`isSpecialExpense` に入れる。

## 5. レシート一覧・詳細

- 詳細・一覧の取得（`lib/receipts/queries.ts`）で `is_special_expense` を読み、`ReceiptDetailItemView.isSpecialExpense` に入れる。
- `ReceiptItemBadges`：`isSpecialExpense` のとき「特別費」バッジ（紫系の色。返金・重複の橙系の印と見分けられるようにする）を最初に表示する。
- `SpecialExpenseReceiptBadge`（レシートの見出しの印）：一覧の行（`ReceiptAccordionItem`）と詳細の見出しの日時の横に出す。文言は `lib/receipts/special-expense-label.ts` の `specialExpenseReceiptLabel(items)` で決める（すべての明細が特別費 →「特別費」、一部 →「特別費あり」、なし → 出さない）。色は明細のバッジと同じ。狭い画面でも印の途中で折り返さない（`whitespace-nowrap`）。
- 分析画面から来たときの条件（`list-params.ts`）：`specialExpense` を条件のパラメータとして読む（値は `normal`／`special` のみ有効）。`DIMENSIONS` に追加するため、`LIST_PARAM_KEYS`・一覧の「条件をクリア」には自動で含まれる。
- 一覧のフィルタ欄（`ReceiptFilterPanel`）には追加しない。分析画面から渡された条件は、絞り込みバナーの表示名（`conditionsLabel`）で「特別費を除く」「特別費」と表示する。
- `drilldown.ts`（`matchReceipt`）：明細の値に `isSpecialExpense` を渡す。

## 6. 分析

### 6.1 項目（`lib/analytics/dimensions.ts`）

| 項目 | 内容 |
|---|---|
| `DIMENSIONS` | 末尾に `"specialExpense"` を追加。ラベル「特別費」 |
| 値（キー） | `"normal"`（通常）／`"special"`（特別費）。定数 `SPECIAL_EXPENSE_KEYS` |
| `dimensionKey` | `isSpecialExpense ? "special" : "normal"` |
| `keyLabel` | 通常／特別費 |
| `keyColor` | 通常＝パレットの1色目、特別費＝2色目（費用区分と同じ決め方） |
| `dimensionOptions` | [通常, 特別費] |
| `conditionsLabel` | `special` は「特別費」、`normal` は「特別費を除く」。他の条件と「・」でつなぐ（例：「食費・特別費を除く」） |

### 6.2 データ（`lib/analytics/queries.ts`）

- 取得の select に `is_special_expense` を追加する。
- `buildAnalyticsRows`：集約のキーに `is_special_expense` を足し、行に `isSpecialExpense` を入れる。

### 6.3 状態と URL（`lib/analytics/url-state.ts`）

- `includeSpecialExpense`：URL の `special=1` のとき true。初期値 false。
- `lib/receipts/list-params.ts` の `ANALYTICS_STATE_KEYS`（「← 分析に戻る」で引き継ぐ項目）に `special` を追加する。
- 次の関数を追加する。

```ts
// 特別費の項目を絞り込み・分けるで選んでいるか（選んでいる間は「含める」を ON とみなす）
export function isSpecialExpenseForced(filter: AnalyticsFilter | null, split: Dimension | null): boolean;

// 集計・一覧への絞り込みに使う条件。filterConditions に、特別費を除くときだけ specialExpense: "normal" を足す
export function analysisConditions(
  filter: AnalyticsFilter | null,
  split: Dimension | null, // 推移グラフでは「分ける」を使わないため null を渡す
  includeSpecialExpense: boolean
): Conditions;
```

- 推移グラフは「分ける」を使わないため、`split` に null を渡す（絞り込みで特別費を選んだときだけ ON とみなす）。

### 6.4 画面（`components/analytics`）

- 新規 `SpecialExpenseToggle.tsx`：「特別費を含める」チェックボックス。`ScopeSelector` の `toggles` に渡し、表示対象のボタンの下に「共同を含める（1/2）」と横一列で並べる（幅が足りないときだけ折り返す）。表示対象（全体・メンバー）に関係なく常に出す。`forced` のときは `checked` かつ `disabled` にし、横に「（絞り込み・分けるで選択中）」と添える。
- `AnalyticsView`：
  - 円グラフの条件は `analysisConditions(filter, split, includeSpecialExpense)`、推移グラフは `analysisConditions(filter, null, includeSpecialExpense)`。
  - 一覧へのリンク（`buildFilteredListHref`）にも同じ条件を渡す。円グラフの行のリンクでは、今までどおり行の値（`split` の値）を条件に重ねる。
  - 見出しの表示名（「食費の合計」など）は、利用者が選んだ絞り込み（`filterConditions(filter)`）から作る（「特別費を除く」を毎回出さないため）。
  - 条件の折りたたみのサマリーには、特別費を含めているとき（強制 ON も含む）だけ「特別費を含む」を足す。

### 6.5 直近12ヶ月の特別費（要件9）

- `lib/analytics/aggregate.ts`：
  - `sumOverMonths(rows, scope, months, conditions, costTypes)`：対象の月全体の合計（`sumByMonth` の各月を足したもの）。
  - `specialExpenseTotal(rows, scope, months, costTypes)`：条件 `{ specialExpense: "special" }` で `sumOverMonths` を呼ぶ。「特別費を含める」とは関係なく特別費だけを足す。
- `AnalyticsView`：
  - 円グラフ・推移グラフのどちらでも、グラフのカードの下に「直近12ヶ月の特別費　〇〇円 ＞」のリンクを置く（グラフの切り替えの外に1つだけ置く。絞り込み・分けるに関係なく出す）。合計が0円のときは出さない（返金でマイナスのときは出す）。
  - 特別費の一覧（6.6節）へ移る（`buildSpecialExpenseListHref(scope, returnState)`）。
- 期間は分析データの `months`（当月を含む12ヶ月）。データは今のもので計算でき、サーバーへの通信は増えない。

### 6.6 特別費の一覧の画面（要件10）

| ファイル | 内容 |
|---|---|
| `app/(app)/analytics/special-expenses/page.tsx` | 画面（Server Component）。期間は分析画面と同じ `lastTwelveMonths(todayKey(now))`。上に「← 分析に戻る」（`BackToAnalyticsButton`＋`ret`）、期間・表示対象・合計、その下に月ごとの見出し（月の合計）と `ReceiptAccordionItem` の行（`match` に「特別費」と按分後の金額・特別費の明細ID） |
| `lib/receipts/queries.ts` の `listSpecialExpenseReceipts` | `receipts` を `special_details:receipt_details!inner(id)` で埋め込み、`.eq("special_details.is_special_expense", true)` で特別費の明細があるレシートだけに絞る。明細（`receipt_details`）は按分のため通常の明細も含めてすべて読む。一覧の行への変換は `listReceipts` と共通の `mapReceiptListRows` |
| `lib/analytics/special-expense-list.ts` | URL（`buildSpecialExpenseListHref`・`parseSpecialExpenseScope`）、表示内容（`buildSpecialExpenseListView`：`matchReceipt` に `{ specialExpense: "special" }` と表示対象を渡し、当てはまるレシートを月ごとに新しい順に並べる）、詳細との行き来（`specialExpenseDetailParams`・`specialExpenseBackHref`） |
| `app/(app)/receipts/[id]/page.tsx` | `from=special-expense` のときは「← 特別費の一覧に戻る」にし、削除後もこの一覧に戻す。編集画面は今の `pickListParams` で `from`・`scope`・`joint`・`ret` を引き継ぐため変更なし |

- 月の判定は分析画面と同じ `monthKeyOf`（サーバーのタイムゾーン＝日本時間）。
- 一覧の合計は `matchReceipt`（分析画面からの絞り込みと同じ按分・重み・符号）で求めるため、分析画面の `specialExpenseTotal` と一致する。
- 通信：分析画面は今までどおり（集計済みの行だけ）。一覧の画面を開いたときに、特別費の明細があるレシートだけを1回読む。

## 10. 実装時の補足

- PostgREST は複数行をまとめて登録するとき、一部の行にだけない列を null として送る（DB の初期値が使われない）。アプリの登録・更新は `buildReceiptDetailRows` で常に `is_special_expense` を送るため影響はない。結合テスト（I-60）で初期値を確かめるときは1行ずつ登録する。
- 分析の取得で `is_special_expense` が null・未指定の行は通常として扱う（`=== true` で判定）。
