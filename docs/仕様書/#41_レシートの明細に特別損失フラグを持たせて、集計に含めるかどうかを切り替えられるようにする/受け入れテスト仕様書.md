# 特別費フラグ 受け入れテスト仕様書（Issue #41）

対象：[要件定義書.md](./要件定義書.md)。
[docs/test-spec.md](../../test-spec.md) の S-M-01〜S-M-10 を、ダミーデータ（11月・10月・9月・7月）の金額で確かめられる形にしたもの。

## 前提

- ローカル環境（Supabase ＋ `npm run dev`）で、ゆうきでログインして確認する。
- マイグレーションを当てておく（`supabase migration up`）。
- 11月に旅行のダミーデータ3件、精算の確認用に7月のダミーデータ1件、特別費の一覧で月ごとに分かれるのを見るために9月・10月のダミーデータ1件ずつを入れておく（既存のデータは消えない。この6件だけ入れ替わる）。
  ```bash
  PGPASSWORD=postgres psql -h 127.0.0.1 -p 55322 -U postgres -d postgres -f supabase/snippets/special-expense-dummy-data.sql
  ```
- 既存の明細はすべて「通常」なので、特別費はこのダミーデータだけになる（11月は No.1〜3、10月は No.5、9月は No.6）。自分で特別費のレシートを登録した場合は、下の値とずれる。

### 11月のダミーデータ（★＝特別費）

| No | 日時 | 支払い先 | 支払者 | 明細（カテゴリ・帰属先） | 支払額 |
|---|---|---|---|---|---:|
| 1 | 11/14 | 箱根の宿 | ゆうき | ★宿泊費 30,000（宿泊・旅行・共同） | 30,000 |
| 2 | 11/15 | 道の駅 | ふみ | ★お土産 2,000（娯楽・ゆうき）、野菜 1,000（食費 ＞ 自炊・共同） | 3,000 |
| 3 | 11/16 | JR東海 | ゆうき | ★新幹線 14,000（交通費・共同） | 14,000 |

No.2 は1枚に特別費（お土産）と通常（野菜）が混ざるレシート。

### 7月のダミーデータ（精算の確認用。AT-15）

| No | 日時 | 支払い先 | 支払者 | 明細（カテゴリ・帰属先） | 支払額 |
|---|---|---|---|---|---:|
| 4 | 7/5 | 温泉旅館 | ゆうき | 宿泊費 20,000（宿泊・旅行・共同）※最初は通常 | 20,000 |

7月のレシートはこの1件だけで、7月の精算は確定していない。12月は未来の月で精算画面を開けないため7月に入れる。
最初は通常にしてあるので、直近12ヶ月の特別費（156,000円など）には入らない。AT-15 で特別費にしたら、確認後に外して戻す。

### 9月・10月のダミーデータ（★＝特別費。AT-10・AT-11・AT-18〜26）

|---|---|---|---|---|---:|

No.5 はふみ個人の特別費（ゆうきの表示対象では出ない）、No.6 は共同の特別費（メンバーの表示対象では半分）。

| AT-03 | 登録画面を開き、明細を2つにする。「一括入力」を開く | 各明細の「特別費」はチェックなし。一括入力の最後に「特別費」のプルダウンがあり、初期値は「変更しない」 | |
| AT-04 | 一括入力で「特別費にする」を選んで「全項目に適用」→ もう一度「一括入力」を開き、「変更しない」のまま帰属先だけ選んで適用 → もう一度開き「特別費にしない」を選んで適用 → 「項目を追加」 | 1回目で全明細にチェックが入る。2回目は「変更しない」で開き、適用しても特別費は ON のまま（帰属先だけ変わる）。3回目で全明細のチェックが外れる。追加した明細はチェックなし | |
