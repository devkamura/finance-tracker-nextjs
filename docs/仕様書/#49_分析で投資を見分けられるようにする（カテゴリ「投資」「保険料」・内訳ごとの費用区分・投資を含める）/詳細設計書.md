# 詳細設計書：分析で投資を見分けられるようにする（Issue #49）

要件：[要件定義書.md](./要件定義書.md)。画面での確認：[受け入れテスト仕様書.md](./受け入れテスト仕様書.md)。
全体仕様書への反映：要件定義書 4.4〜4.6節・基本設計書 3.5節・5.4〜5.6節・用語と算出方法 1章・3.3節・5〜6章・画面仕様書 03・05・07・10。

## 1. 方針

- 投資は**支出として記録したまま**、カテゴリ「投資」で見分ける。分析で含める・除くを切り替える（初期値は除く）。
- 除く仕組みは、特別費（Issue #41）と同じく「集計・一覧の絞り込みに使う条件」に足す。グラフと一覧の「うち」金額は同じ関数（`matchesConditions`）で判定するので、ずれない。
- 費用区分は、内訳 → カテゴリの順に決める。決める場所は `lib/analytics/dimensions.ts` の `costTypeOf` の1か所だけにする。

## 2. DB（`supabase/migrations/20261126000002_investment_category.sql`）

| 変更 | 内容 |
|---|---|
| `categories` に2行 | 「投資」「保険料」（`default_cost_type = 'fixed'`）。`seed.sql` にも同じ行を足す |
| `category_breakdowns.cost_type` | `text`、`check (cost_type in ('fixed','variable'))`。既存の内訳には今のカテゴリの費用区分（グループの設定 → カテゴリの初期値）を入れる。作るときに指定がなければ BEFORE INSERT トリガー `fill_breakdown_cost_type` が同じ規則で入れる。空は CHECK 制約 `category_breakdowns_cost_type_required` で禁止（NOT NULL にすると、生成される型で作るときに毎回渡す必要があるため CHECK 制約にした）。カテゴリの費用区分を変えても内訳は変わらない。RLS は既存の内訳のポリシー（編集は管理者）のまま |
| 内訳の作成 | 既存のグループごとに「投資 ＞ 積立（NISA）」（fixed, 並び順1）・「個別株」（variable, 並び順2）。同名があれば作らない（`category_breakdowns_name_uniq`） |
| 明細の付け替え | タグ「投資」（同じグループのタグ）が付いた明細の `category_id`・`breakdown_id` を「投資 ＞ 積立（NISA）」に。精算確定済みの月も含む（マイグレーションは RLS を通らない。金額・帰属先は変えないので精算は変わらない） |

- これから作るグループには投資の内訳を自動では作らない（設定 ＞ カテゴリで作る）。
- カテゴリは ID 順に並ぶため、「投資」「保険料」は「その他」の後ろになる（既知の制約）。

### 3.2 費用区分の決め方（`lib/analytics/dimensions.ts`）

```ts
export type CostTypeMap = {
  byCategory: Map<number, CostType>;  // カテゴリID → 費用区分
  byBreakdown: Map<number, CostType>; // 内訳ID → 費用区分
};
export function costTypeMap(categories, breakdowns = []): CostTypeMap;
export function costTypeOf(values, costTypes): CostType; // 内訳 → カテゴリ → "variable"
```

- `dimensionKey(…, "costType", …)` は `costTypeOf` を使う。呼び出し側（分析画面・一覧）は `costTypeMap(categories, breakdowns)` で作る。

### 3.3 投資を除く条件

| 場所 | 変更 |
|---|---|
| `lib/analytics/dimensions.ts` | `Conditions` に `excludeCategory?: string` を追加。`matchesConditions` は、明細のカテゴリが `excludeCategory` なら当てはまらない。`conditionsLabel` は「投資を除く」のように出す。`INVESTMENT_CATEGORY_NAME = "投資"`・`investmentCategoryId(categories)`（名前で見分ける。ID は環境ごとに違うため） |
| `lib/analytics/url-state.ts` | `AnalyticsState.includeInvestment`（URL の `investment=1`、初期値 false）。`isInvestmentForced(filter, investmentCategoryId, breakdowns)`：絞り込みが投資のカテゴリ、または投資のカテゴリの内訳なら true。`analysisConditions(filter, split, includeSpecialExpense, excludeCategoryId = null)`：4つ目を渡すと `excludeCategory` を足す |
| `lib/receipts/list-params.ts` | 条件のパラメータの一覧 `LIST_CONDITION_PARAM_KEYS` を一元管理し、一覧の画面（`ReceiptListView`）もこれを使う（受け入れテストで、画面側の別の一覧に `excludeCategory` がなく、条件が捨てられていた不具合を直した）。一覧の URL に `excludeCategory` を追加（`buildFilteredListHref`・`parseListFilter`。存在しないカテゴリは無視）。「← 分析に戻る」の状態に `investment` を追加 |

- 分析画面では `excludeCategoryId = includeInvestment || investmentForced ? null : investmentId` を、円グラフ・推移グラフ・一覧へのリンクの条件に渡す。
- 「直近12ヶ月の特別費」（`specialExpenseTotal`）は変えない（投資を含める・除くに関係しない）。

## 7. 既知の制約

| 内容 | 対応 |
|---|---|
| カテゴリは ID 順に並ぶため、「投資」「保険料」は「その他」の後ろ | 必要になったらカテゴリに並び順の列を足す |
| これから作るグループには、投資の内訳が自動でできない | 設定 ＞ カテゴリで作る |
| タグ「投資」を付けていない投資の明細は、自動では付け替わらない | 画面で「投資」に直す |
| 「投資を含める」がオンのまま費用区分で分けると、投資も固定費・変動費に入る | 生活費だけを見たいときはオフにする（画面仕様書 07 に記載） |
