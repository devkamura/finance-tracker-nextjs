# レシート一覧のフィルタ 受け入れテスト仕様書（Issue #39）

対象：[docs/全体仕様書/要件定義書.md](../../全体仕様書/要件定義書.md) 4.5節（Issue #39）。
[詳細設計書.md](./詳細設計書.md) の「テスト項目」の R-M-01〜R-M-11 のうち、主要なものを11月のダミーデータの金額で確かめられる形にしたもの。

## 前提

- ローカル環境（Supabase ＋ `npm run dev`）で、ゆうきでログインして確認する。
- 11月のダミーデータを入れておく（既存のデータは消えない。この6件だけ入れ替わる）。
  ```bash
  PGPASSWORD=postgres psql -h 127.0.0.1 -p 55322 -U postgres -d postgres -f supabase/snippets/receipt-list-filter-dummy-data.sql
  ```
- 11月に自分で別のレシートを登録した場合は、件数・合計が下の値とずれる。

### 11月のダミーデータ（6件・合計 8,190円）

| No | 日時 | 支払い先 | 支払者 | 明細（帰属先） | 支払額 |
|---|---|---|---|---|---:|
| 1 | 11/2 | イオン | ゆうき | 野菜・肉 3,000（共同）、ティッシュ 800（ゆうき） | 3,800 |
| 2 | 11/5 | STARBUCKS 渋谷店 | ふみ | カフェラテ 600（ふみ） | 600 |
| 3 | 11/10 | マツモトキヨシ | ふみ | 目薬 1,000（ゆうき）、化粧水 1,500（ふみ）、洗剤 1,000 税別10%（共同） | 3,240 |
| 4 | 11/15 | サイゼリヤ | ゆうき | ランチ 2,400（共同） | 2,400 |
| 5 | 11/20 | ユニクロ | ふみ | ニット 2,000（ふみ）**返金** | −2,000 |
| 6 | 11/24 23:30 | セブン-イレブン | ゆうき | ホットコーヒー 150（ゆうき） | 150 |

No.3 は1枚に ゆうき・ふみ・共同 が混ざるレシート。税込合計 3,600 を1割引の 3,240 で按分し、目薬 900・化粧水 1,350・洗剤 990 になる。

## 確認項目

レシート一覧（11月）を開き、「絞り込み」を押して条件を選ぶ。各項目の前に「条件をクリア」で条件を外しておく。

| No | 操作 | 期待結果 | 結果 |
|---|---|---|---|
| AT-01 | ユーザー「ゆうき」・基準「支払者」を選ぶ | No.1・4・6 の **3件・6,350円**。一覧の上に「支払者：ゆうき　3件・¥6,350」が1行で出る | |
| AT-02 | 基準を「負担者」に切り替える | No.1・3・6 の **3件・1,850円**。No.3 の行に「うち 900円」が出る | |
| AT-03 | 続けて「共同1/2を含む」をオンにする | No.1・3・4・6 の **4件・5,045円**。No.3 は「うち 1,395円」（900＋990÷2） | |
| AT-04 | ユーザーを「ふみ」に変える（負担者・共同1/2を含むのまま） | No.1〜5 の **5件・3,145円**。AT-03 の 5,045円との合計が全体の 8,190円になる | |
| AT-05 | 期間を 11/24〜11/24 にする。次に期間の横の「クリア」を押す | No.6 だけ（**1件・150円**）。23:30 のレシートも 11/24 に入る。「クリア」で開始日・終了日がまとめて外れ、6件に戻る | |
