# 用語と算出方法

このアプリで使う名詞（用語）と、画面に出る数字の算出方法の一覧。
分析・精算・家計相談（FP相談）で同じ言葉を同じ意味で使うための基準とする。

- 最終更新：2026-11-26（dev ブランチ 4cc0d65 時点のコードから作成。Issue #47 で全体仕様書に移した）
- 根拠のコードを各項目に示す。関連：[要件定義書.md](./要件定義書.md)・[基本設計書.md](./基本設計書.md)

## 1. 用語

### 1.1 人

| 用語 | 意味 | DB | 備考 |
|---|---|---|---|
| グループ | 家計を共有する単位。最大2人 | `groups` / `group_members` | |
| メンバー | グループに所属する人 | `group_members.user_id` | |
| 相方 | ログインユーザーから見た、もう1人のメンバー | — | 複製登録で使う（`lib/receipts/duplicate.ts`） |
| 支払者 | そのレシートを実際に支払った人 | `receipts.payer_user_id` | 新規登録時は登録者本人。編集で変更できる |
| 登録者 | そのレシートを入力した人 | `receipts.created_by` | 複製登録では、支払者と登録者が異なる |
| 帰属先 | その明細が「誰のための支出か」 | `receipt_details.owner_user_id` | メンバーのID、または `NULL`＝**共同** |
| 共同 | 2人の共通の支出。帰属先が `NULL` の明細 | `owner_user_id IS NULL` | 精算では2人で折半する |
| 相手 | その支出が「誰と・誰のため」か（分析用の分類） | `receipt_details.counterpart_id` → `counterparts` | 既定：メンバー各人・ふたり・友人・実家。帰属先とは別物（下の注意を参照） |

> **帰属先と相手の違い**
> 帰属先は**お金の負担**を決める（精算に効く）。相手は**分析の分類**で、精算には効かない。
> 例：友人へのプレゼントを自分のお金で買った → 帰属先＝自分、相手＝友人。

### 1.2 レシートと明細

| 用語 | 意味 | DB | 備考 |
|---|---|---|---|
| レシート | 1回の会計 | `receipts` | |
| 日時 | 会計の日時。**月の判定はこの日時（日本時間）で行う** | `receipts.occurred_at` | 登録日ではない |
| 支払額 | 実際に支払った金額（実支払額）。ポイント・クーポン適用後 | `receipts.amount` | 常に正の値で保存する |
| 取引種別 | 「支出」または「返金」 | `receipts.transaction_type_id` → `transaction_types` | 返金は集計でマイナスにする |
| 支払い先 | お店・支払い先 | `receipts.payee_id` → `payees` | `NULL`＝手入力（登録外）。分析では「登録外」にまとめる |
| 複製登録 | 2人が同じ内容の買い物をしたとき、相方の分を同時に登録する機能 | `receipts.is_duplicated = true` | 支払者＝相方の**別のレシート**として登録される |
| 明細 | レシート内の1品目 | `receipt_details` | |
| 明細の金額 | 入力した価格 | `receipt_details.price` | 税込または税別。常に正の値 |
| 税区分 | 明細の金額が税込か税別か | `receipt_details.tax_type`（`inclusive` / `exclusive`） | |
| 税率 | 税別の明細の税率（8% / 10%） | `consumption_taxes.multiplier`（1.08 / 1.10） | 税込の明細では使わない |
| 特別費 | 旅行など、ふだんは発生しない支出 | `receipt_details.is_special_expense` | 明細ごとに設定する（Issue #41） |
| タグ | 明細に付ける任意の目印（複数可） | `receipt_detail_tags` → `tags` | 現在の分析の集計には使っていない |

### 1.3 分類

| 用語 | 意味 | DB | 備考 |
|---|---|---|---|
| カテゴリ | 支出の大分類。アプリ共通の固定マスタ | `categories` | 食費・日用品・衣類・ファッション・交通費・通信費・賃料・水道光熱費・娯楽・宿泊・旅行・医療費・学習・自己投資・その他・投資・保険料 |
| 投資 | NISA の積立・個別株の購入など、資産を増やすために出したお金。カテゴリ「投資」で記録する（内訳：積立（NISA）・個別株） | `categories.name = '投資'` | 分析では初期値で除く（「投資を含める」）。保険料は投資ではない（固定費） |
| 内訳 | カテゴリの下の小分類。グループごとに設定する | `category_breakdowns` | 未設定の明細は「内訳なし」 |
| 費用区分 | 固定費か変動費か。**内訳のある明細は内訳の費用区分、内訳のない明細はカテゴリの費用区分**（明細ごとには選ばない） | `category_breakdowns.cost_type`（必須）。内訳のない明細は `category_settings.cost_type`、なければ `categories.default_cost_type` | 初期値：賃料・水道光熱費・通信費・投資・保険料が固定費、ほかは変動費。内訳の費用区分は、内訳を作るときにそのときのカテゴリの費用区分が入り、あとは内訳ごとに固定費・変動費を選ぶ（カテゴリの費用区分を変えても、内訳の費用区分は変わらない）（Issue #49） |

### 1.4 分析・精算の用語

| 用語 | 意味 | 備考 |
|---|---|---|
| 表示対象 | 分析で誰の支出を見るか。「全体」または「メンバー1人」 | `Scope`（`lib/analytics/types.ts`） |
| 共同を含める | 表示対象がメンバー1人のとき、共同の明細を**1/2**計上するか | |
| 特別費を含める | 分析の集計に特別費の明細を含めるか。**初期値は含めない** | 「分ける」「絞り込み」で特別費を選んだときは常に含める |
| 投資を含める | 分析の集計にカテゴリ「投資」の明細を含めるか。**初期値は含めない**（Issue #49） | 「絞り込み」で投資のカテゴリ・内訳を選んだときは常に含める |
| 分ける | 円グラフをどの項目で分けるか | カテゴリ・内訳・費用区分・支払い先・相手・特別費 |
| 絞り込み | 集計する明細を、ある項目の値に限る | 同上の項目 |
| 精算期間 | 精算の単位。**1か月**（日時の月） | `settlement_periods` |
| 精算の確定 | その月の精算額を確定する。確定した月のレシートは編集・削除できない | 確定・再オープンは管理者だけ |

## 2. 金額の算出の流れ（共通）

分析も精算も、まず**レシートの支払額を明細に按分**し、その按分額を集計する。

```text
レシート（支払額）
  │
  ├─ 1. 明細の税込換算額 = 税込なら 価格 / 税別なら floor(価格 × 税率)
  │
  ├─ 2. 按分額 = 支払額 × 明細の税込換算額 ÷ 全明細の税込換算額の合計
  │        ・各明細を floor で切り捨て、余りは税込換算額が大きい明細から1円ずつ足す
  │        ・按分額の合計は必ず支払額と一致する
  │        ・全明細の税込換算額の合計が0円なら、按分額はすべて0円
  │
  └─ 3. 取引種別が「返金」なら、按分額をマイナスにする
```

- 実装: `allocateReceiptAmount`（[lib/settlement/calculate.ts](../../lib/settlement/calculate.ts)）
- 設計: [基本設計書.md](./基本設計書.md) 3.2節（レシート・明細の列）
- つまり**分析の金額は、税込・ポイント値引き後・返金差し引き後**の金額

例：食品1,000円（共同）＋化粧品1,000円（B）、ポイント500円を使って支払額1,500円 → 各明細の按分額は750円。精算では A の負担 375円、B の負担 1,125円（共同 750円の半分 ＋ 個人 750円）になる。

- ポイント・クーポン・値引きは、誰のものか・どの明細に効いたかを記録しない。明細の合計と支払額の差は、すべて上の比率で各明細に配分する
- 支払額は「実際に支払った金額」の1つだけを持ち、「レシートに書かれた合計金額」のような別の金額は持たない

## 3. 分析の数字

実装: [lib/analytics/queries.ts](../../lib/analytics/queries.ts)（取得・按分）、[lib/analytics/aggregate.ts](../../lib/analytics/aggregate.ts)（集計）

### 3.1 対象データ

- **当月を含む直近12か月**のレシート（日時が対象月に入るもの）。当月は途中までの金額になる
- 複製登録のレシートも、通常のレシートとして含める（実際に2人がそれぞれ支払った支出のため）
- 明細のないレシートは含めない

### 3.2 表示対象による重み

| 表示対象 | 帰属先＝その人 | 帰属先＝共同 | 帰属先＝もう1人 |
|---|---|---|---|
| 全体 | 1 | 1 | 1 |
| メンバー（共同を含める：オン） | 1 | **1/2** | 0 |
| メンバー（共同を含める：オフ） | 1 | 0 | 0 |

- 「誰が払ったか（支払者）」ではなく、**「誰のための支出か（帰属先）」**で集計する
- 共同の1/2で生じる0.5円は丸めずに表示する（例：375.5円）

### 3.3 指標

| 指標 | 算出方法 |
|---|---|
| 月の支出（推移グラフの棒） | その月の明細の按分額 × 重み の合計。特別費を含めない設定なら特別費の明細を、投資を含めない設定ならカテゴリ「投資」の明細を除く |
| 前月比 | 当月 ÷ 前月 × 100（小数第1位）。最初の月・前月が0円以下・当月がマイナスの月は出さない |
| 円グラフの各値 | 選んだ月で、「分ける」項目の値ごとに 按分額 × 重み を合計 |
| 円グラフの％ | 各値 ÷ プラスの値の合計。返金で合計がマイナスになった値は扇から外して注意書きに出す |
| 12か月の合計 | 推移グラフの12か月分の合計 |
| 特別費の合計 | 直近12か月の特別費の明細だけの合計（「特別費を含める」の設定に関係なく出す） |

### 3.4 レシート一覧の絞り込みとの関係

分析画面から一覧に移ったときの「当てはまる金額」は、分析と同じ按分額・重みで計算するので、グラフの値と一致する。ただし、一覧のアコーディオンで表示する明細の金額は**入力した価格のまま**（按分前）。

## 4. 精算の数字

実装: `calculateSettlement`（[lib/settlement/calculate.ts](../../lib/settlement/calculate.ts)）、設計: [基本設計書.md](./基本設計書.md) 3.3節・5.8節

| 指標 | 算出方法 |
|---|---|
| 負担額 | 帰属先ごとに按分額を合計。共同は2人に1/2ずつ。丸めはAだけ四捨五入し、Bは合計から逆算する |
| 実支払額 | 支払者ごとに支払額を合計（返金はマイナス） |
| 個人立替額 | 支払者と帰属先（共同以外）が異なる明細の按分額の合計 |
| 精算差額 | 実支払額 − 負担額 |
| 最終精算 | 精算差額がマイナスの人が、プラスの人へ絶対値分を支払う |

## 5. 家計相談（FP相談）で使うときの対応

家計相談スキル（`japan-fp-advisor`）にデータを渡すときの言葉の対応。

| 相談での言葉 | このアプリで対応する数字 | 注意 |
|---|---|---|
| 世帯の月の生活費 | 表示対象「全体」・特別費を含めない・投資を含めない月の支出 | 2人分の個人の支出も含む |
| 本人の月の生活費 | 表示対象「本人」・共同を含めるオン・特別費と投資を含めない | 共同は1/2 |
| 毎月の投資額 | カテゴリ「投資」の合計（「絞り込み：カテゴリ＝投資」） | 内訳で積立（NISA）と個別株に分かれる |
| 特別費 | 特別費の明細（めったにない支出） | 月の生活費には含めず、貯蓄・ボーナスから出す別枠として扱う。毎年ある出費（帰省・年払い）は特別費にせず通常の支出として記録する |
| 固定費 | 費用区分「固定費」の合計（投資を含めない） | 内訳 → カテゴリの順に決まる |
| 保険料 | カテゴリ「保険料」の合計 | 固定費。投資ではない |

**このアプリに記録されていないもの**（相談の前に別途確認が必要）

- 収入（給与・ボーナス）、資産の残高（預貯金・NISA）
- カテゴリに対応がない支出：税金・ふるさと納税の寄付・ローン返済（記録する場合は「その他」などに入っている可能性がある）
- 口座引き落とし・カード払いで、レシートとして登録していない支出
