## 1. 目的

2人で使う家計簿アプリ。「誰がいくら払ったか」を記録するだけでなく、次のことを目的とする。

1. 毎月の支出を、カテゴリ・内訳・相手・支払い先・費用区分などの切り口で分析し、どこに多く使っているかを把握する
2. 2人それぞれが本来負担すべき金額と、実際に支払った金額を把握し、どちらがどちらにいくら払えば公平かを算出する（精算）
3. 月ごとの支出の推移を確認し、支出の見直し・家計の改善に使う
4. レシートを画像として保存し、紙のレシートを管理する手間を減らす

## 2. 利用者とグループ

- 1つの**グループ**を、**管理者を含めて最大2人**で使う。3人目は登録できない
- グループを作成した人が**管理者**になる。もう1人は**一般メンバー**
- ログインは Google 認証（Supabase Auth）だけ。メールアドレス・パスワードなどほかの認証方式は持たない
- ユーザーは、自分が所属するグループのデータだけを閲覧・操作できる。URL の直接指定やサーバーアクションの直接呼び出しでも、他グループのデータは取得・変更できない（DB の行レベルの権限で保証する）
- データは将来、1つの Google アカウントが複数のグループに所属できる形にしておく（今はグループの切り替え画面は持たない）

## 3. 基本の考え方

支出は、次の別々の軸で記録する。

| 軸 | 表すもの | 付ける単位 |
|---|---|---|
| カテゴリ ＞ 内訳 | 何に使ったか | 明細ごと |
| 費用区分 | 固定費か変動費か | カテゴリごと（内訳ごとにも設定できる。自動） |
| 相手 | 誰と・誰のための支出か | 明細ごと |
| 支払い先 | どこで使ったか | レシートごと |
| 支払者 | 実際にお金を払った人 | レシートごと |
| 帰属先 | 最終的に誰の負担か（メンバー、または共同） | 明細ごと |
| 特別費 | ふだんは発生しない支出か | 明細ごと |
| タグ | そのほかの目印 | 明細ごと（任意・複数） |

- **支払者と帰属先は別物**として扱う。A が B の物を買ったら、支払者＝A・帰属先＝B で、A が立て替えたことになる
- 1枚のレシートに、共同・A・B の明細が混在してよい
- **共同**の支出は、精算では常に2人で折半する

## 4. 機能要件

### 4.1 ログイン・グループ・メンバー

- まだどのグループにも所属していないユーザーは、ログイン後にグループ作成画面へ誘導する。グループ名を入力して作成すると、作成した人がそのグループの管理者になる。すでにグループに所属している人は作成できない
- 管理者は、メンバーを Gmail アドレスで事前登録できる。その人が初めて Google でログインしたときに、自動でグループのメンバーになる（アドレスは小文字化・前後の空白を除いて比べる。同じアドレスは重複登録できない。招待メールは送らない）
- 管理者は、メンバー（管理者自身を含む）の表示名と色（ブルー／レッド）を設定できる。一般メンバーは表示名を変更できない
- 管理者は、一般メンバー・招待中のメンバーをグループから外せる。管理者自身は外せない。外しても Google アカウント自体は削除しない

### 4.2 レシートの登録・編集・削除

- レシートには、支払い先・日時・取引種別（支出／返金）・支払額・画像（任意）と、1件以上の明細を登録する
- 明細には、商品名・価格・税区分（税込／税別）・税率（税別のときだけ。8%／10%）・カテゴリ・内訳・相手・帰属先・タグ・特別費を登録する
  - 内訳を設定したカテゴリでは、内訳は必須。内訳が1つだけなら自動で選ぶ
  - 相手は必須
- 支払者は、新規登録ではログインしている本人になる。編集画面では、メンバー全員が支払者を変更できる
- **支払額は実際に支払った金額**（ポイント・クーポン適用後）とし、明細の合計と一致しなくてよい（一致するかの確認はしない。以前あった不一致の警告は廃止した）
- **画像の読み取り（OCR）**：レシート画像から、支払い先名・日時・支払額・明細（商品名・価格）を読み取ってフォームに入れる（Gemini API）。税率は商品名から推定した値を初期値として入れるだけで、税区分・価格は推定しない。ユーザーは保存前にすべての値を確認・修正できる。読み取りに使った画像は、そのレシートの画像として保存する。OCR を使わずに画像だけを保存することもできる
- **一括入力**：すべての明細のカテゴリ・内訳・相手・帰属先・タグ・特別費を、まとめて同じ値にできる
- **複製登録**：2人がそれぞれ同じ買い物をしたとき、新規登録画面で「相方の分も同じ内容で登録する」を選ぶと、支払者＝相方の同じ内容のレシートも1件登録する
  - 明細の帰属先は「私」を「相方」に置き換え、「相方」「共同」はそのまま
  - 2件とも登録するか、どちらも登録しないかのどちらか（片方の登録に失敗したら、もう片方も取り消す）
  - 複製で作られたレシートには「複製」の印を付け、相方が内容を確認するきっかけにする。印は編集しても消えない
  - 登録後の2件は、独立したレシートとして編集・削除・集計・精算する
- 精算を確定した月のレシートは、登録・編集・削除できない（4.8節）

### 4.3 支払い先

- 支払い先はグループで1つの一覧を共有する。名前はグループの中で一意
- 登録・名前の変更・別名の追加と削除・共通の既定値の変更・削除は、**メンバー全員**ができる。削除できるのは、レシートで使われていない支払い先だけ
- **表示／非表示**：メンバーごとに、その支払い先を自分のプルダウンに出すかを切り替えられる。相方のプルダウン・過去のレシート・分析には影響しない。新しく登録した支払い先は全員に表示する
- **既定値**：支払い先ごとに、カテゴリ・内訳・相手・帰属先・タグ・商品名の既定値を持てる
  - **共通の既定値**：支払い先に1セット。登録後もメンバー全員が変更できる。相手・帰属先には「登録する人」（入力している本人に置き換わる）を選べる（Issue #44）
  - **自分用の既定値**：メンバーが自分の分だけ持つ上書き。一式まるごと持つ。自分用がないメンバーには共通の既定値を使う。相方の自分用は見られるが変えられない
  - 支払い先を選んだとき（選び直したとき・明細を追加したとき・画像の読み取りで選ばれたときを含む）に、使う既定値を明細に入れる。カテゴリ・内訳・相手・帰属先・タグは全明細を上書きし、既定値がない項目は未選択にする。商品名は、空の明細にだけ入れる
  - 登録済みのレシートは、編集画面を開いただけでは変えない
- **別名**：支払い先ごとに別名を複数登録できる（例：オーケー ← オーケー長津田店）。同じ別名・支払い先の名前は、グループの中で重複できない
  - 別名を登録すると、店名が一致する過去のレシート（支払い先に紐づいていないもの）を、その支払い先に切り替える。精算確定済みの月も含め、明細は変えない。別名を削除しても戻さない
- **店名の照合**：手入力・画像の読み取りの店名を、グループのすべての支払い先の名前・別名と完全一致（前後の空白は無視）で照合する
  - 手入力：保存したときに、支払い先（ID・店名）だけを設定する。既定値は入れない
  - 画像の読み取り：自分が表示している支払い先に一致したら、その支払い先を選び、既定値を入れる。自分が非表示にしている支払い先に一致したら、支払い先だけを設定する

### 4.4 分類の設定

ヘッダーの「設定」から、次を登録・編集する。

| 項目 | 内容 | 編集できる人 |
|---|---|---|
| カテゴリ | カテゴリ自体はアプリ共通の固定の一覧（「投資」「保険料」を含む）。グループごとに、内訳（追加・編集・削除・非表示）と費用区分（固定費／変動費）を設定する。費用区分は内訳ごとにも設定できる（Issue #49） | 管理者 |
| 相手 | 既定の相手（メンバー各人・ふたり・友人・実家）は表示／非表示だけ切り替えられる。任意の相手を追加・編集・削除できる | 管理者 |
| タグ | 追加・編集・削除・非表示 | メンバー全員 |
| 支払い先 | 4.3節 | メンバー全員 |

- 費用区分の初期値は、賃料・水道光熱費・通信費・投資・保険料が固定費、それ以外が変動費。内訳の費用区分は、内訳を作るときにそのときのカテゴリの費用区分が入り、あとは内訳ごとに固定費・変動費を選ぶ（カテゴリの費用区分を変えても、内訳の費用区分は変わらない）。費用区分を変えると、過去の月の集計も新しい区分で表示する
- **投資**（NISA の積立・個別株の購入など）はカテゴリ「投資」で記録する。投資の明細は、帰属先・支払者とも本人にしておけば精算に影響しない。**保険料**は投資ではなく、カテゴリ「保険料」（固定費）で記録する
- 非表示にした内訳・相手・タグは、登録画面のプルダウンに出さない。すでに付いている明細は、そのまま表示・集計する
- レシートで使われている内訳・相手・タグ・支払い先は削除できない（削除ボタンを非活性にし、理由を表示する）。支払い先の既定値で使われているだけなら削除でき、既定値はその項目を「設定しない」に戻す
- レシートの入力画面の相手のプルダウンでは、ログインしている本人を「自分（A）」と表示する

### 4.5 レシート一覧・詳細

- 一覧は月ごとに表示する。各レシートは開閉でき、明細と画像をその場で確認できる
- 明細には、カテゴリ（内訳）・相手・帰属先・税区分・タグ・特別費のバッジを表示する。レシートの見出しには、全明細が特別費なら「特別費」、一部なら「特別費あり」の印を出す
- **フィルタ**（Issue #39）：月の中で、次の条件を組み合わせて（AND）絞り込める。絞り込みは画面の中だけで行う
  - ユーザー：支払者（そのユーザーが払ったレシート）または負担者（そのユーザーの負担分がある明細を含むレシート。共同の1/2を含めるかを選べる）
  - 期間：選んでいる月の中の開始日〜終了日
  - キーワード：支払い先名・商品名の部分一致（英字の大文字・小文字は区別しない）
  - 絞り込み中は、条件と該当件数を表示する。合計は表示しない（投資・特別費を含むかが条件で変わり、何の合計か分かりにくいため。合計は分析画面で見る。Issue #49）
- **分析画面からの絞り込み**：分析画面の表・推移グラフから、同じ条件（月・表示対象・絞り込み・分けた値・特別費・投資）で絞り込んだ一覧に移れる。各レシートに「うち〇〇円」を表示する（すべてのレシートの「うち」の合計は、分析画面の金額と一致する）。「← 分析に戻る」で元の分析画面に戻る
- 条件は URL に残し、詳細・編集画面から戻っても条件を保つ
- 詳細画面では、レシートと明細、画像、複製の印を表示し、編集・削除ができる（精算確定済みの月はできない）

### 4.6 支出分析

- 当月を含む直近12か月のデータを、画面を開いたときに1回だけ取得し、以降の切り替えはサーバーと通信せずに画面の中だけで行う
- 金額の算出方法は [用語と算出方法.md](./用語と算出方法.md) 2〜3章に従う（按分後・税込・返金はマイナス）
- **表示対象**：全体／メンバー。メンバーのときは帰属先で振り分け、「共同を含める」をオンにすると共同の1/2を含める（初期値オフ）
- **円グラフ**：選んだ月の支出を、「分ける」の項目（カテゴリ・内訳・費用区分・支払い先・相手・特別費）ごとに表示する。表に金額と割合を出す
- **推移グラフ**：12か月の月ごとの金額（棒）と前月比（折れ線・100%の基準線）を表示する
- **絞り込み**：円グラフ・推移グラフとも、1つの項目の値（例：カテゴリ＝食費）で絞り込める
- **特別費を含める**：初期値オフ（特別費の明細を除く）。「分ける」「絞り込み」で特別費を選んでいる間は、常に含める。グラフの下に「直近12ヶ月の特別費」の合計を出し、押すと特別費の一覧（`/analytics/special-expenses`）に移る
- **投資を含める**（Issue #49）：初期値オフ（カテゴリ「投資」の明細を除く）。給料から投資していて、投資も支出として見たい人はオンにする。「絞り込み」で投資のカテゴリ・内訳を選んでいる間は、常に含める
- 返金で金額がマイナスになった値は、グラフでは0として描き、数字は実際の金額で表示する。その場合は必ず注意書きを出す
- 選択状態は URL に残し、戻る・再読み込みで元に戻す

### 4.7 特別費

旅行など、ふだんは発生しない支出を明細ごとに「特別費」として記録し、ふだんの支出の相場をつかめるようにする（Issue #41）。

- 登録・編集画面で明細ごとに設定できる（一括入力も可）
- 分析では初期設定で除き、切り替えで含められる（4.6節）
- 精算には、特別費も通常どおり含める
- 特別費の一覧：直近12か月の特別費の明細を含むレシートを、月ごとに新しい順に並べる。金額は表示対象に合わせた按分後の金額で、合計は分析画面と一致させる

### 4.8 精算

- 月ごと（日時の暦月）に、2人それぞれの負担額・実支払額・個人立替額・精算差額と、最終的にどちらがどちらにいくら払うかを表示する。算出方法は [用語と算出方法.md](./用語と算出方法.md) 4章
- 精算の基準は、明細の合計ではなく**支払額**とする
- **管理者だけ**が、月ごとに精算を**確定**できる。確定した月は、その時点の結果を保存して表示し、その月のレシートの登録・編集・削除を禁止する
- **管理者だけ**が、確定した月を再オープンできる。再オープン中はレシートを変更でき、改めて確定すると結果を上書きする（確定の履歴は残さない）

## 5. 非機能要件

| 観点 | 要件 |
|---|---|
| 利用環境 | スマートフォンで見やすく操作しやすい画面にする |
| 応答性 | 分析画面・レシート一覧の絞り込みは、画面を開いた後の操作でサーバーと通信しない |
| データ量 | 1年分の明細が DB の1回の取得上限（1,000件）を超えても、漏れなく取得する |
| 時刻 | 日本時間（JST）だけで運用する。月の区切りは JST の暦月 |
| セキュリティ | 他グループのデータは、画面・サーバーアクション・DB のすべてで取得・変更できない。API キーなどの秘密情報はサーバーだけで扱う |
| アクセシビリティ | 状態を色だけで伝えず、文言やアイコンを併記する |
| 外部サービス | テストでは、Gemini API などの外部サービスへの通信は必ずモックにする |

| 内容 | 状態 |
|---|---|
| 分類の支援「お助け」（Yes／No の質問でカテゴリ・帰属先を決める機能） | 未着手 |

| タグでの集計、絞り込みの複数組み合わせ | 未着手 |
| 3人以上での利用・精算 | 対象外 |
| Google Drive へのレシートの保存 | 廃止（レシートは DB と Supabase Storage に保存する） |
